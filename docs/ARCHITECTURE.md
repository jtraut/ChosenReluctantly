## 2. Scene and run flow

There are two entry scenes:
- `scenes/main/RunMain.tscn` is the project's main scene. It is an inherited instance of `Main.tscn` with `run_mode = true` plus `RunController`, `RunHud`, `RoomClearedScreen` and `WinScreen` (both `RunPromptScreen`, the second with `kind = "win"`).
- `scenes/main/Main.tscn` is the endless arena (looping waves from `data/waves.json`, no rooms). Tests, `wave_sim` (without `--run`), `ReloadCycle` and scenarios use it.

`Main.tscn` children: `WorldEnvironment`, `Sun`, `Floor` (CSG box), `ArenaWalls` (invisible static walls), `Player`, `CameraRig`, `EnemySpawner`, `Hud`, `BossHpBar` (a `scenes/ui/BossHpBar.tscn` instance), `GameOverScreen`, `SettingsScreen`, `DebugOverlay`.

`Main._ready` ([src/main/Main.gd](../src/main/Main.gd)):
1. Hands the player to the camera rig, the spawner, the HUD and the debug overlay; gives the player the camera for aiming.
2. Attaches `AimIndicator`, `PlayerOcclusionCue` and `PlayerCues` to the player; registers itself with `WorldRef` (`_enter_tree`).
3. `_setup_run_mode`: if `uses_run_mode(run_mode, user args)` (pure static: `run_mode` is true and there is no `--scenario` arg) and `data/run.json` is valid, calls `RunController.begin(self)`. Otherwise it removes the run nodes (`RunController`, `RunHud`, `RoomClearedScreen`, `WinScreen`) so the scene is the endless arena. An invalid `run.json` logs an error and falls back to the arena.
4. `_check_starting_deck`, then `SceneSelfCheck.find_problems` (`push_error`s if the world would render empty).
5. If user args follow `--`, sets up scenario and screenshot capture (`Main._setup_debug_capture`).

Deck check: `Main` checks the deck rules (`DeckRules.run_start_block_message`). A short deck is blocked: `push_error`, the spawner is switched off, and `Main.run_start_blocked(message)` is emitted. The shipped deck passes.

### Run flow (Milestone 3a)
- **Config:** `data/run.json` (section 6) is loaded and validated by `RunConfig`. `RunGenerator.generate(seed, config)` returns the room list (each entry has `index`, `type`, `wave_id`) from a seeded shuffle that follows `composition` and `placement` (boss last, first room combat, elite and rest inside index ranges); BD2 then turns one combat room into the relic room (`_place_relic_rooms`, own seeded RNG). The same seed gives the same rooms.
- **State:** `RunState` holds seed, room index, `character_id` (W1a; saved as `character`; an old save without it loads as the Rogue, an unknown id logs an error and falls back to the Rogue), HP and max HP, deck ids, rejects left, history, outcome, and (3b) `pending`, `offer` and `choice_log`. It serializes with `to_json`/`from_json` (`FORMAT_VERSION` 2; a v1 dict loads with no pending choice). `RunSession.current` (a static, not an autoload) keeps it between scenes; `RunSession.begin_new_run` is the only way to start a fresh one (it consumes `forced_seed` once). `RunSession.full_deck` (`--full-deck`) makes new runs start with every card of the character's pools (`CharacterDatabase.full_deck`) instead of its `starting_deck`, and stays on for the launch. `RunSession.selected_character`, `character_forced` and `chosen_character()` hold the class for the next run.
- **Class pick (W1a):** `Main._choose_character` runs from `_enter_tree` (before the Player's `_ready`, because the class sets pools, HP, body colour and attacks) and calls `RunController.prepare`, which parses the launch args and gives the Player its `character_id`. `ClassPickScreen` ([src/ui/ClassPickScreen.gd](../src/ui/ClassPickScreen.gd), a child of `RunMain.tscn`; `ClassPickCard` draws one class) opens on every run, pauses the room, and on confirm calls `RunController.confirm_class_pick(id)`. That remembers the pick (`CharacterPick.remember`), starts a fresh run as that class (same seed and start room) and swaps the scene; a run in progress keeps its class. `ClassPickScreen.should_open(state)` is false when `--class` or `--deck` was given, headless, or in the arena or a scenario; `--show-class-pick` forces it. `CharacterPick` keeps the last pick in memory and, in windowed play only, in `user://last_class.json` (never in headless, `-s` scripts or tests). Look and words: `data/ui.json` `class_pick`.
- **A room:** `RunController.begin` puts the state's HP and deck on the player, builds the room's finite wave table (`RunConfig.room_wave_config`), configures the spawner with it and a seed from `room_spawn_seed(run_seed, room_index)`, and emits `room_started`. `_process` watches `EnemySpawner.room_cleared()`. A rest room and (BD2) a relic room are finished at once (spawner off; the relic room's offer then opens). `_finish_room` sets `Health.damage_immune` on the player (so a projectile in flight can't kill a winner), records history, and on the last room emits `run_won`. Otherwise it calls `RunRelics.open_for_room` (BD2; it hands every room that isn't an elite or relic room to `RunChoices.open_for_room`); if that opens a choice it emits `choice_requested(model)`, else `room_cleared` (the plain Continue panel; with the shipped data every non-final room opens a choice).
- **Choices (3b):** after a won combat room (and, with `relics.enabled` false, an elite room; with relics on, an elite or relic room opens a relic offer instead, see Relics) `RunChoices` opens a card reward (3 offers from `RewardOffer`, or reject all); a rest room opens the rest menu (heal, or a per-card removal list with Back). `RunController.choose(option_id)` resolves one option through `RunChoices.apply`, heals the player for a heal option, emits `choice_resolved(result)` and, when the choice is finished, goes to the next room at once. A non-final step (open the removal list, Back) re-emits `choice_requested`. `RunState.pending` and `offer` persist the open choice, so a reload resumes it (`RunController._resume_choice`) instead of replaying the room. Details in the choice model section below.
- **Next room:** `RunController.continue_to_next_room(force := false)` bumps the index and calls `Main.swap_to_fresh_scene`. It does nothing while a choice is open; `force = true` discards the choice and is for tests and the reload soak only (a qa test scans `src` and `tools` for other callers). A fresh scene resets cooldowns, shuffle bags, zones, statuses and timers; the `RunState` carries HP and the deck.
- **Death:** `Player.player_died` goes through the normal death beat to Game Over, which shows "Reached room X of Y". Try again and New run both call `Main.restart_arena`, which in run mode does `RunSession.begin_new_run()` (new seed) and swaps the scene.
- **Launch args** (`RunController._apply_launch_args`, first scene of a launch only): `--run-seed=N`, `--run-room=K` (1-based), `--run-clear-after=S` (debug: clears that room after S seconds), `--full-deck` (debug), `--class=<rogue|wizard>` and `--show-class-pick` (W1a; `--class` is parsed in `DebugDecks.resolve_launch` so it can be checked against `--deck`: a bare, repeated or unknown `--class`, or one that disagrees with the preset's class, exits 2). `RunPromptScreen` also reads `--run-auto-choose=<option ids>` (debug: picks those option ids in turn as choices open, skipping the arm delay).
- **Tiers:** a wave spawn can carry `tier` (`elite` or `boss`). `EnemySpawner` calls `Enemy.apply_tier(tier_id, cfg)` with the `data/run.json` `tiers` entry: HP multiplier, resistance via `TierRules.resistance` (the larger of own and the floor, capped), rank, and a `TierMarker`. The shipped boss takes its HP and rules from `data/bosses.json` (see the Boss section), so the HP, armor and resistance fields of `tiers.boss` are probably dead; the entry is still read (`RunConfig`, the marker colour and size, tests), so it stays (game-lead, MAP3 sitting A; cleanup goes to BD3). MAP3 adds `tiers.mini_boss` (same fields as `elite`, plus `scale` and marker values), applied to a spawn with `"tier": "mini_boss"`. `TierRules` handles the elite and the mini-boss.
- **UI:** `RunHud` shows "Room X of Y - Type" with a `RunTypeIcon` (shapes from `RunIcons`: circle combat, diamond elite, plus rest, star boss; placed by `HudLayout.room_indicator_rect`, top right since 3c). `RunController.boss_spawned(boss)` and `current_boss()` expose the room's boss. `RunPromptScreen` is a generic panel (icon, title, subtitle, flavour line, label/value rows, `options_box`, one action button). `show_content(dict)` fills it; the text rows come from `RunPromptRows`. 3b rewards use it through `show_choice(model)` (see the choice model section). `TierMarker` is the flat diamond/star sign above an elite's or boss's HP bar (shape, not colour, and no bigger body). Look and sizes: `data/ui.json` `run_ui`; words: `data/run.json` `ui`.

### The branching map (MAP1)
Plan: `docs/MAP.md`; calls: `docs/DECISIONS.md` (MAP1 entries). Config: `data/map.json` (section 6).
- **Pure core, no scene:** `MapConfig` (loader and validator; unknown keys rejected at every level), `MapGraph` (helpers over `{nodes, edges}`: `next_ids`, `start_ids`, `boss_id`, `all_paths`, `first_route`, `normalize`), `MapRules` (shape, type and path rules, and `relic_estimate`), `MapGenerator` (seeded grid walks, then type draws, wave ids, and a chest-size post-pass on its own stream). The generator and the 1000-seed sweep share `MapRules`. Node id = `(room - 1) * columns + column`; the boss is alone on room 10.
- **A map run** is a run whose `RunState` holds a map (`RunNodes.active(state)`); the data switch only decides what a new run gets (`RunSession.map_override` from `--map` / `--no-map`, else `MapConfig.enabled()`; parsed by `MapLaunch`). `RunState` carries `map`, `path` (node ids taken; the last is the current room), `gold` and `xp_earned`; `from_dict` drops the map loudly when `path` and `room_index` disagree.
- **Flow:** `RunController.begin` opens `RunState.PENDING_NODE` at run start (`RunNodes.open`; the class pick still comes first, only at that start). After a room's reward or relic step finishes, the controller opens the pick again instead of walking on. `RunController.pick_node(id)` = `choose("node:<id>")` -> `RunChoices.apply` -> `RunNodes.apply` appends the node to `path`, moves `room_index`, and the next room is a fresh scene. `RunNodes` is pure and static over the state and a context dict (`RunNodes.shipped_context()`, inside `RunChoices` ctx under `nodes`): reachable ids, `node_info` (hover text from data, chest, gold range), options, `roll_gold`. The rooms of a map run are built from the map's nodes, each with its `node_id`.
- **Gold** is paid once at `RunController._finish_room`: `RunNodes.roll_gold(run seed, node id, type, run.json gold)` (seeded, so a reload cannot pay twice), added to `RunState.gold`, then `gold_changed(total, delta)`. Merchant purchases lower it through `Merchant` (`gold_changed` then carries a negative delta). The generator also enforces `min_rest` (D40): `MapRules.min_rest_over_paths` and `MapGenerator._fewest_rests` count the fewest rests on any path in one pass over the rooms (not a walk of every path).
- **Relic stage and chest:** a `relic_room` node has no fight and offers relics at once; its chest size (small, medium, large) picks the tier-weight row (`map.json` `chests`: this act's row, the next act's, or act 3's) and a `min_tier`.
- **`--run-room=N`** in a map run lays the path along `MapGraph.first_route` (no gold for the skipped rooms).
- **Route bots** (`src/run/RouteBot.gd`, pure): `first`, `relic`, `safe`, `random`. They live in the run sim (`tools/wave_sim.gd -Run`), because `tools/bot_sim.gd` builds no rooms.
- **UI** (`src/ui/`): `MapScreen` (pick mode when `choice_requested` carries the node choice; view mode from the pause screen), `MapCanvas` (lines and one `MapNodeButton` per node), `MapNodeButton` (draws the type shape with `RunIcons`; no logic), `MapLayout` (pure geometry, focus order, default focus), `GoldBadge` (HUD and map header; the "+N" on a payout). `MapScreen` sits on layer 11, above the HUD gold badge. Look: `data/ui.json` `map_screen`; words: `data/run.json` `ui.map`.
- **Relic cues** (display only): `RelicCueLayer` + `RelicCues` (pure merge/cap/stack rules) float a relic's name and ring at the point it fired (taken from the last `relic:<id>` hit or status position, else the player); `RelicProgress` draws "n/N" pips on an every-Nth relic's chip from `RelicManager.trigger_progress(relic_id)`.
- **Reload soak:** `run_reload_cycle.ps1 -Map` adds a map pass; without it the soak pins the straight run.

### The merchant (MAP2)
Plan: `docs/MAP.md` section 4.4; calls: DECISIONS "MAP2-A", "MAP2-B" and "MAP2 ux" entries. Numbers: `data/run.json` `merchant` and `relics.prices`.
- **Model, no scene:** `Merchant` ([src/run/Merchant.gd](../src/run/Merchant.gd)) is pure and static over a `RunState` and the `RunChoices` context. `open_visit` draws the stock from (run seed, node id) into `RunState.merchant_visit` (relic ids, card ids, what is sold, node, reroll count); `close_visit` clears it. `buy_relic`, `buy_card`, `buy_removal` and `reroll` return `{ok, kind, id, price, reason, needs_giveup, giveable, gave_up}`; `reason` is a code the UI words (`data/run.json` `ui.merchant.reasons`). Relic stock = a shop-only slot first (`merchant.shop_only_slots`, relics whose `sources` are exactly `["merchant"]`, falling back to normal stock), then normal `RelicOffer.offer("merchant")` slots; cards come from `RewardOffer`. Removal price = `removal_base` + `removal_step` x `RunState.merchant_removals`, and goes through `RunChoices.removal_problems` (the deck minimums).
- **Choice model:** `RunMerchant` turns the visit into the generic choice model. Three pending values, so a save lands on the same screen: `RunState.PENDING_MERCHANT` (the shop), `PENDING_MERCHANT_REMOVE` (the removal list), `PENDING_MERCHANT_SWAP` (a relic bought at the relic cap: pick which owned relic to give up, BD2's step; `relic_incoming` holds the relic). Option ids: `buy_relic:<id>`, `buy_card:<id>`, `merchant_remove_menu`, `merchant_remove:<card>`, `merchant_reroll`, `merchant_leave`, `merchant_back`, `merchant_giveup:<id>`, `merchant_cancel`. `RunChoices` routes to it for `room_type == "merchant"` and for those pendings (`ctx["merchant"]` = `MerchantConfig.shipped_context()`; `RunMerchant.sync` sets `free_rerolls` from the owned relics' `merchant.free_rerolls` modifiers on every entry). A merchant room has no fight.
- **UI hook:** `RunController.merchant_view()` (`RunMerchant.view`: items with price, sold, can_buy and a reason code, gold, the removal list with per-card reasons, rerolls, the swap) and the calls `buy_relic`, `buy_card`, `open_merchant_removal`, `buy_removal`, `merchant_back`, `reroll_merchant`, `give_up_for_purchase`, `cancel_purchase`, `leave_merchant`, all through `choose`. `RunPromptScreen` draws it with `RunOptionCard.Look.SHOP` tiles (`SHOP_KINDS`), two columns, Remove/Reroll/Leave in the footer. A purchase emits `gold_changed` with a negative delta.
- **The switch:** `MerchantSwitch` + `data/merchant_on.json` (a `{map, run}` patch merged into the loaded configs for one process: `--merchant`, `run_wave_sim.ps1 -Merchant`, `run_map_print.ps1 -Merchant`). The shipped data has the merchant on, so the patch equals the data; `MerchantSwitch.shipped_problems` fails a test if the four lines (`types.merchant.weight`, `path_rules.relic_route`, `estimate.merchant_prices`, `relics.prices`) disagree with the patch while the weight is above 0. To turn the merchant off, revert all four lines (weight 0, `relic_route` [5, 7], the earlier estimate and prices) and run the sweep; weight 0 alone with `relic_route` [6, 8] is unlikely to generate (284 of 1000 seeds failed at the old estimate, per DECISIONS "MAP2-B").
- **Bots:** `MerchantPolicy` (pure, no random draws, reads what it bought from `choice_log`): the `relic` route buys relics cheapest first, then a removal, then a card; `safe`, `first` and `random` buy a removal, then a card. Wired in `tools/wave_sim.gd`.

### Choice model (Milestone 3b)
- `RunChoices` ([src/run/RunChoices.gd](../src/run/RunChoices.gd)): pure and static over a `RunState` and a context dict (`RunChoices.shipped_context(pools)` builds it from the databases; tests pass fixtures). Functions: `open_for_room(state, room_type, is_last_room, ctx)` (sets `pending`/`offer`), `model`, `options`, `apply(state, option_id, ctx)`, `removal_problems` (wraps `DeckRules.can_remove`). It never reads card ids or names; the one place that looks inside a card is `CardSummary`.
- **Option dict** (every key always present): `id` ("card:<id>", "skip", "heal", "remove_menu", "remove:<id>", "back"), `kind` (card, remove, heal, skip, back), `label`, `detail`, `flavor`, `card_id`, `slot_type`, `slot_name`, `count`, `enabled`, `reason`, `costs_reject`, `opens_list`, `amount`.
- **Model dict** (`RunChoices.model`): `choice` (reward, rest or rest_remove), `title`, `line`, `options`, `rejects_remaining`, `rejects_max`. `RunController.current_choice()` adds `room_label`, `room_type`, `room_type_name` and `next_line`.
- `apply` returns `{ok, kind, card_id, amount, finished, reason}`. A disabled or unknown option changes nothing and returns `ok = false`. Picks and removals change `RunState.deck`; every resolved option is appended to `choice_log` (`pick`, `reject`, `heal`, `remove`).
- `RewardOffer.generate(run_seed, room_index, deck, cards, pools, pool_defs, rewards)`: own RNG stream from `offer_seed`, candidates sorted by id, weights from `rewards.unowned_weight` / `owned_weight`, distinct, up to `offer_size`. **BD3a:** the optional trailing args `starter` and `removed` carry two rules. *Removed cards (D47 = B):* ids in `RunState.removed_cards` (`record_removal`, called when a deck-clean removal resolves) are never candidates, in card offers and in `Merchant`'s card stock, even when a copy is still in the deck. *Status lean (D43 = B):* an unowned card that applies status S weighs x (1 + `rewards.status_lean` x n_S), capped at `rewards.status_lean_max`; n_S counts copies in the deck of cards applying S, a card with two statuses takes the larger factor, the element pool's own status is not counted, a `detonate_status` effect is not a source, and with `rewards.status_lean_skip_starter` true (D46 = B) only `RewardOffer.added_cards(deck, starter)` count (a pruned-then-repicked starter card still counts as starter). A missing or 0 `status_lean` turns the lean off. Card field `requires` (`slot_types`, `pools`, `status_sources`) is checked by `meets_requires` and validated in `CardSchema` (`RewardOffer.validate_requires`).
- `CardSummary.effect_line(card, slot_base_cooldown, text)` builds a line like "12.0 fire damage (aoe), Burn 5.0 s. Cooldown 3.3 s" from effect templates and params. Buff wording comes from `run.json` `ui.effect` plus the slot names.
- **Screen:** `RunPromptScreen.show_choice(model)` builds one `RunOptionCard` per option into `options_box`. `layout_for` picks `row` (reward cards), `actions` (rest tiles) or `grid` (removal list, one column per slot); `look_for` maps kind to card look. Number keys do nothing (director, 2026-11-02; `digit_target` was removed in PL3 and two doc comments in `RunPromptScreen.gd` still mention it); arrow keys move the highlight; Enter or a click confirms (`option_chosen`, then `RunController.choose`). Options are armed `run_ui.prompt_option_arm_delay` seconds after opening (`options_armed()`, `disarm()`), Space is swallowed, input is ignored while paused, and focus is restored after a pause. Sizes and colours: `data/ui.json` `run_ui` keys starting `option_`. **Fit:** `_fit_panel` shrinks the whole panel to the window; an offer never scrolls (floor `offer_min_fit_scale`), only the removal grid scrolls (floor `option_min_fit_scale`). A `CenterContainer` resets its child's scale on every sort, so the scale is kept in `_fit_scale` and re-applied on the container's `sort_children` signal (`_apply_fit_scale`); the panel sits under the HUD band (`_avail_height`). Locked-removal and "Slot N now: A / B / C" words come from `run.json` `ui.rest.remove_locked` and `ui.option.slot_now`; the effect-line wording from `ui.effect`.

Death and restart:
- `Player.player_died` (from `Health.died`) -> `Main._on_player_died` starts slow-mo and shake via `Juice`. The beat is timed in `Main._process` from `Time.get_ticks_usec()` (paused time excluded), because Godot's ignore_time_scale timer overcounts the frame where the time scale changes.
- When the beat ends `Main` calls `Main._announce_game_over`, which emits `Main.game_over_ready` once. `GameOverScreen` listens, shows itself, and on "Try again" calls `Main.restart_arena()`.
- `restart_arena()` (in run mode it starts a new run first) calls `swap_to_fresh_scene()`, which resets `Juice` and `GamePause`, unpauses, and replaces the scene with a fresh copy of itself in the same place in the tree (deferred; it does not rely on `current_scene`, so it works inside VpCapture). If the scene has no parent or file path it falls back to `reload_current_scene()`. The fresh scene resets everything that lives in the scene (HP, decks, cooldowns, enemies, waves, statuses). Autoload state does not reset on its own, which is why `Juice.reset()` and `GamePause.reset()` are called first.

## 4. Core systems

### Player ([src/player/Player.gd](../src/player/Player.gd), `scenes/player/Player.tscn`)
- `CharacterBody3D` with child nodes `Health`, `StatusEffectManager`, `Hurtbox` (team "player"), body mesh.
- Movement is relative to the fixed camera; aim is the mouse ray on the ground plane (`get_aim_point`, `get_aim_direction`).
- Owns: `card_slots` (a `CardSlotController`), `stat_modifiers` (a `StatModifiers`), `attacks` (an `AttackController` built in `_setup_attacks`), `cast_input` (`CastInput`), `cast_preview` (`CastPreview`).
- Character identity is `character_id` (export; a key of `data/characters.json`; "" = infer from `owned_pools`, else the Rogue). `_apply_character` takes pools, max HP and body colour from `CharacterDatabase`. `owned_pools` is still an export but is empty by default: it is filled from the character unless a test or capture sets its own. There is no character creation beyond the class pick.
- Dodge: `start_forced_move` with i-frames. **The dodge is on (H3; it was off in the H2 trial):** `data/player.json` `dodge.enabled` (optional; a missing value reads as the built-in default, true; `PlayerConfig` fallback is enabled true, charges 2) is read through `PlayerConfig.dodge_enabled()` (tests flip it with `PlayerConfig.set_dodge_enabled`; `Player.dodge_enabled()` forwards it). When false, the dodge never fires, charges freeze, and `get_dodge_state()["enabled"]` is false (the HUD `DodgePips` row hides itself on that flag, polled each frame). The `dodge` action is bound to Space in `data/input_bindings.json`; with the switch on and no key, startup logs an error from `InputLabels.find_missing_required` (called by `InputBindings`). `Hurtbox.set_invulnerable` makes i-frames by zeroing the hurtbox collision layer, so attack queries skip it. Dodge speed, duration, per-charge recharge time, charge limits and post-pause block ticks come from `data/player.json` through `PlayerConfig` (copied into `dodge_speed` etc. in `_ready`). **Charges (P-dodge):** `Player.dodge_charges` is a `DodgeCharges` ([src/player/DodgeCharges.gd](../src/player/DodgeCharges.gd), pure `RefCounted`): a dodge spends one, and while below the maximum one charge returns every `cooldown` seconds, one at a time. The maximum is `Player.dodge_charges_max()`: the class count (`CharacterDatabase.dodge_charges`, else `dodge.charges`) through the `dodge_charges` stat modifiers, rounded and clamped to `min_charges`..`max_charges` (`DodgeCharges.effective_max`). A lowered maximum clamps the current count at once. No dodge while a forced move is running or at 0 charges. Charges refill on a new room (a fresh `Player`) and on Try again. `Player.get_dodge_state()` gives the HUD `current`, `max`, `recharging`, `recharge_progress`, `recharge_remaining`, `available`, `enabled`.
- `start_forced_move(direction, speed, duration, invulnerable, vfx_look)` is shared by the dodge and the "dash" effect template. It ends exactly at `speed * duration` and stops dead (S6-2).
- **Aim override (BD3a fix, a9d56fc):** `Player.aim_point_override` (a Vector3 or null) replaces the mouse ray. `_apply_aim` honours it, so the body turns toward it like toward the mouse and cones, projectiles and dashes use that facing. Only `tools/wave_sim.gd` (the sim bot) and `Scenario` (key `aim_point_offset`) set it; it is null in real play. Before the fix `_apply_aim` ignored it, so every headless sim bot faced a fixed direction; bot-measured numbers from before are stale.
- Input model: light/heavy clicks and card keys are latched in `_unhandled_input` (so a UI screen can swallow them); movement and dodge poll `Input`. Latched casts and clicks are consumed on the next physics tick. Pause, death, focus loss and a cast-trigger change call `cancel_cast_preview()`.
- Solid bodies: if `data/player.json` `body.collide_with_enemies` is true (shipped), the player's mask includes the enemy layer and enemies' masks include the player layer; both use `platform_floor_layers = WORLD` so neither can ride the other. `EnemySpawner` positions an enemy before `add_child`. `pass_through` clears the enemy bit for a time (static flag); when it ends inside an enemy, collision returns only once the player is clear (3 s cap). False restores the old walk-through behaviour.
- `Player.default_rng_seed` (static, -1 = random) seeds the card and status RNGs for sims. Knockback (PL3): `_knockback_velocity` is added to `velocity` each tick, and `_applied_knockback` remembers what was added so the next tick takes it out before reading the walking velocity back (it used to compound: a 9 m/s hit carried 19.6 m, now 2.25 m); it is zeroed while a forced move (dodge, dash) drives the velocity. Signals: `player_died`, `pass_through_changed`, `damage_dealt`, `dodge_charges_changed(current, maximum)` (also fires when only the maximum changes), and forwarded `attack_started/fired/ready/cancelled(attack_id)` for the HUD meters.

### Camera ([src/camera/CameraRig.gd](../src/camera/CameraRig.gd))
Fixed-angle isometric rig. Root follows `target`; child `Camera3D` keeps a fixed offset plus shake jitter. Orthographic. `Juice.register_camera_rig` lets `Juice.screen_shake` reach it.

### Combat and damage
- `Hurtbox` (Area3D) has a `team` and paths to `Health` and `StatusEffectManager`. Attacks find hurtboxes by physics query (`MeleeQuery.find_hurtboxes_in_cone / in_sphere`), skipping the caster's own team (no friendly fire).
- `Health.take_damage(amount, type, knockback, source, kind)` is the single choke point (a static audit test guards it, see sharp edges). It picks one mitigation channel from the damage type (see Armor and mitigation below), lowers HP (never below `Health.hp_floor`, default 0; the boss raises it to its next phase threshold so one hit cannot skip a phase) (ignored while `Health.damage_immune` is true; the run sets it on a won room), emits `damaged`, `health_changed`, and `died` once.
#### Armor and mitigation (slice A1, GDD section 7)
- Two channels, chosen by damage type in `Health.take_damage`. `ArmorConfig.is_non_elemental(type)` true (`physical`, `neutral`, from `data/armor.json`): **armor**. Anything else (fire, ...): **resistance** (`Health.resistances` through `CombatMath.apply_resistance`, capped by `resistance_cap`). Armor never touches elemental damage and resistance never touches physical or neutral.
- Armor: reduction = `armor / (armor + K)`, clamped to the cap (`CombatMath.armor_reduction`). K and the cap are in `data/armor.json`, loaded and validated by [src/combat/ArmorConfig.gd](../src/combat/ArmorConfig.gd), which also holds the stat names (`armor`, `armor_penetration`) and a parity check (armor and resistance of one tier must give reductions within 2 points).
- `Health.get_armor()` = `base_armor` through the `armor` stat in `StatModifiers`. Penetration is flat, read from the *source's* `armor_penetration` stat, subtracted from armor before the formula. The player's base armor is 0; the Wizard card Ward, Technically (`buff` template, additive `armor`, `data/cards/wizard_ward.json`) is the first player armor source. `Health.last_source_id` (W1b) holds the instance id of the last damage source (0 if none); it is telemetry for the sim's `-BossLog`, not gameplay.
- Where armor values live: tier armor in `data/run.json` `tiers` (elite, boss), boss armor in `data/bosses.json` (tiered enemies use the larger of their own and the tier). Numbers: read those files.
- DoT: Bleed (physical) goes through armor, Burn (fire) through resistance; heals ignore both. Ticks are floats, so tiny ticks stay fractional.
- After the hit, `Health.last_channel` (`CHANNEL_ARMOR` / `CHANNEL_RESISTANCE` / `CHANNEL_NONE`) and `last_reduction` are valid inside `damaged` handlers. The owner passes them to `Juice.on_hit_landed` -> `spawn_damage_number` -> `DamageNumber.style_for`: armor shows `[9]` muted grey, resisted shows `<4>`, and only when the reduction is at least `armor_min_reduction` / `resist_min_reduction` (`ui.json` `damage_numbers`). The style is part of the merge key, so styled numbers never fold into plain ones.
- Display of defense: boss bar shield pip and "Armor N% - Resists ..." text (`BossHpBar`); elite shield pip (`EnemyHpBar`, shader `assets/shaders/enemy_hp_bar.gdshader`, size `hp_bars.pip_scale`); F3 "Defense" block (`DebugOverlay`: enemy under the cursor, else nearest, plus the player).
- Scenario setup hits (the debug harness lowering enemy HP) bypass armor on purpose.
- `Player._on_damaged` and `Enemy._on_damaged` call `Juice.on_hit_landed` (damage number; hit-stop and shake **only for `Health.KIND_HIT`**, not `KIND_DOT` ticks or `KIND_ECHO` follow-up hits) and apply their own hit flash and knockback.
- `Health.take_damage(..., source, kind)` emits the source's `damage_dealt(target, removed, damage_type, kind)` (HP actually removed, after resistance). Leech listens to it through `StatusEffectManager.on_damage_dealt`.
- Layers: `CollisionLayers` (World 1, Player 2, Enemy 4, Hurtbox 8, Hitbox 16), named in `project.godot`. Player and enemy bodies are solid to each other (see Player).

### Card slots and decks
- `CardSlot` ([src/cards/CardSlot.gd](../src/cards/CardSlot.gd)): pure `RefCounted`. A shuffled mini-deck (draw pile, discard pile) over the cards owned for one slot type, plus a cooldown. Cooldown = slot base + card `cooldown_modifier`, then `StatModifiers`, floored. Swapping a dead card is blocked while cooling.
- `CardSlotController`: builds the five slots in `SLOT_TYPE_ORDER` (attack_single, attack_aoe, utility, movement, recovery), filters cards by `owned_pools`, and on `try_use(slot_type)` casts the revealed card through `EffectTemplates`. Emits `card_cast`.
- Keys: `slot_1..5` to use, Shift plus the same key (`dead_card_swap_1..5`) to swap. The keys are data (`data/input_bindings.json`; today Q, E, F, Ctrl, R; dodge is Space), not code.

### Deck rules
- `data/deck_rules.json` -> `DeckRules` (pure static logic; `shipped_config()` is cached because the F3 overlay reads it every frame). Config: `min_unique_per_slot`, optional `slots: {slot: {min_unique}}`, optional `slot_groups: [{name, slots, min_unique_total}]`. Copies never count twice.
- `DeckRules.check(...)` returns a `DeckCheck` (per-slot and per-group `count/required/short`, `problems`, `summary_lines()`). `can_remove` / `can_swap` return the problems a change would cause (empty = allowed); they only block on the card's own slot and groups. `CardSlotController.deck_check()`, `can_remove`, `can_swap` wrap them for the live deck.
- `DeckRules.validate_shipped_content()` (run by a test, not at boot) checks the shipped pools against the minimums. `Main` blocks run start on a short deck (section 2).
- **Debug preset decks (T-decks).** `DebugDecks` ([src/run/DebugDecks.gd](../src/run/DebugDecks.gd)) reads `data/debug_decks/*.json` (`read_dir`), validates each preset with `DeckRules`, and parses `--deck=<name>` / `--list-decks` (`resolve_launch`). `RunController._apply_launch_args` sets `RunSession.debug_deck`; `RunSession.begin_new_run` then builds the deck from the preset's `starter`, or `full` with `--full-deck` (`DebugDecks.deck_of`). It is sticky for the launch, so Try again keeps it. Bad args quit with exit 2 from `RunController.begin`; `--deck` is ignored with `--scenario` and in the arena. Presets are legal decks: there is no rule bypass.
- The shuffle is a true bag: it refills from all owned copies when empty, and never repeats the card just drawn across a reshuffle (when another unique card exists).

### Held-key casting (Slice 6)
- `CastInput` tracks which slot key is held. In `release` mode (default, `data/settings.json`) press starts a preview and release casts; in `press` mode press casts at once.
- `CastPreview` draws the held card's exact hit area on the ground (shapes from `CastPreviewShapes`, sizes from `VfxSizing`, same numbers as the hit query; look from `data/cast_preview.json`). `Player.get_preview_state()` exposes it to tests and the HUD.

### Effect templates ([src/combat/EffectTemplates.gd](../src/combat/EffectTemplates.gd))
An effect in a card's `effects[]` is `{template, params, condition?}`. `condition` (BD1, optional, validated by `CardSchema` through `EffectCondition.validate`) skips the effect when false. Types built (`EffectCondition.TYPES`): `target_has_status {status_id}` (per target hit, only on cone, aoe, projectile, zone and apply_status), `cast_within {slot_type | tag, seconds}` (checked once per cast against `CastHistory`; seconds above 0 and at most 6) and `zone_active {}`. The later BUILD_DEPTH condition types are rejected until built. Authoring rule: a conditional effect must come before the effect that applies the status it tests.

Eleven reusable effects: `projectile`, `cone`, `aoe`, `dash`, `heal`, `apply_status`, `buff`, `zone`, `pass_through`, `reduce_cooldown` (BD2: `seconds` and exactly one of `slot_type` or, BD3a, `attack_id` `light` or `heavy`; used by relics) and `detonate_status` (BD3a: `status_id`, `multiplier`). `REQUIRED_PARAMS` is the single source of truth for each template's required params; `CardSchema` validates against it. `EffectContext` carries `caster`, `spawn_parent`, `caster_team` and `last_hits` (hurtboxes the previous effect in the same card hit, which `apply_status` targets). Optional params (the list in the file header is authoritative):
- BD1: `aoe` `anchor: "caster"` (the disc stays where the caster stood at cast time; an error together with `max_range`). `buff` `consume_on_cast` (a slot type id or a tag) and `charges` (1 to `MAX_BUFF_CHARGES`) make a **primed** buff, consumed by later matching casts (`StatModifiers.add_primed_modifier`; a skipped cooldown uses the stat `slot_cooldown_skip.<slot>`, and a card never eats its own prime). A buff on the stat `status_damage_mult.<status>` scales the caster's status ticks (`StatusEffectManager.STATUS_DAMAGE_MULT_PREFIX`).
- BD3a: `detonate_status` hits every target in `last_hits` that holds a damage-over-time status: its remaining ticks at once (x `multiplier`, x stacks) as a `KIND_HIT` with the card's origin, then the status ends with reason `detonated` (`StatusEffectManager.detonate_status`). It is not a status source for `requires.status_sources` or the lean. Like `apply_status` it needs an earlier effect that hit something. `projectile` and `dash` accept `status_id` + `status_duration`: each hit applies the status (a dash needs `hit_radius` to apply one with no damage; Excuse Me is the example).
- `projectile`: `yaw_degrees` (turn the shot about the vertical axis, a fan). Code-only (W1a, set by the attack code, not by cards): `direction` (replaces the caster's facing) and `lane` (preview lane on or off). `look` ({color, scale, optional ball_scale}, the bolt's own look) is set by the Wizard's auto bolt and, since PL3, by card data: the colour is a hex string in a card, `EffectTemplates.resolved_look` turns it into a Color and `validate_look` checks it (scale and ball_scale 0.1 to 5; `ball_scale` resizes only the drawn ball, never the hit radius). Used by `wizard_bolt_volley` and `wizard_overqualified_bolt`. `aoe`: `vfx` (false skips the impact visual; the boss draws its own).
- Any damaging effect: `knockback_strength`; `hits` + `hit_interval` (cone, aoe, projectile, apply_status; `hit_interval` required when `hits` > 1). Follow-up hits re-query from the caster's live position and stop if the caster is gone.
- `apply_status`: `chance` (rolled on the seeded `status_rng`), `target: "self"`.
- `cone`: `vfx` (false skips the wedge). `aoe`: `center` (code-only, targeted heavies), `max_range` (place at the clamped aim point), `delay` (centre locks at cast, telegraph grows).
- `dash`: `invulnerable`, `direction_mode` (`forward` | `away_from_aim`), path damage (each enemy hit once as `KIND_HIT`). `pass_through` (bool): the mover passes through enemies for exactly the move (`Player.start_forced_move(..., pass_through)`); a move that ends inside a body keeps the ghost restore (up to 3 s until clear). Set on the six movement dash cards. The dodge never passes through. Without it, bodies are solid and a dash stops at the first enemy.
- `zone`: ground circle or line (a line runs across the cast direction) that ticks damage and an optional status chance for `duration`; placed at the aim point clamped to `max_range`; first tick at placement. `ZoneManager` (one per world, `ZoneManager.for_world`) owns the live zones; `data/zones.json` `max_live` caps them (the oldest ends first) and `look` holds the visuals. A zone ends with its caster. Ticks are `KIND_DOT`.
- `pass_through`: `duration`. Overlapping grants end with the last. A static flag clears enemy masks so enemies spawned mid-buff are included; it resets on end, death and `_exit_tree`.

### Tags, keywords and slot cues (BD1)
- **Tags** are derived from a card's effects by `CardTags` (Projectile, Melee, Area, Zone, Dash, Heal, Burn, Bleed, Buff; conditional effects count) and **keywords** are authored in the card's optional `keywords` array and defined in `data/keywords.json` (`KeywordDatabase`: `display_name`, `rule_text`; today Primer, Payoff, Keystone). Both share one capitalised spelling, so a condition `tag` or a buff `consume_on_cast` can name either. `CardDatabase.tags_for(card_id)` / `has_tag` read the table computed at load.
- **Cast history:** `CardSlotController` puts `CombatEvents.history` and the clock on the `EffectContext` (`cast_history`, `now`), runs the effects, then notifies the relay, so a card never sees its own cast.
- **HUD side:** `SlotSynergyView.infos(player)` returns per slot `chips`, `keywords`, `keyword_rules`, `condition_text`, `condition_live`, `primed`, `primed_time_left`, `primed_duration`, `primed_charges`. `Hud` hands each to its `CardSlotWidget`, which draws a `ChipRow`, the LIVE glow and the primed marker (`SlotCues` holds the easing). `RunOptionCard` shows chips on reward and removal cards. `CardSummary.condition_text` writes the condition sentence. Look values: `data/ui.json` `hud`.
- **Plan bot:** `PlanPolicy` decides cast, swap or wait per slot from the `condition` data (never a card id), using the same `SlotSynergy` view. The wave sim `-Plan` and the bot sim `--plan` use it.

### Relics (BD2)
Relics are run-long passives: stat modifiers plus triggers on combat events. Content is data (`data/relics/<id>.json`, 19 shipped, 3 of them shop-only); the engine is below. Plan: `docs/BUILD_DEPTH.md` section 4; calls: `docs/DECISIONS.md` ("BD2" entries).
- **The relay** ([src/core/CombatEvents.gd](../src/core/CombatEvents.gd)). Events: `card_cast`, `hit_landed(target, amount, damage_type, kind, origin, position)`, `enemy_killed(target, position, origin, statuses)`, `status_applied`, `status_ended(.., reason, ..)`, `attack_fired`, `dash_ended` (card dashes only, not the dodge), `dash_passed_through(card_id, count, position)` (BD3a: a card dash that passed through enemies; never the dodge), `player_damaged`, `zone_started/ended`, `room_started`, `room_cleared` (also fires for rest rooms). Emitters call `notify_*` next to their own signals. `status_ended` reasons: `expired`, `owner_died`, `consumed`, and (BD3a) `detonated` (Pyre Insurance ignores it, so a Burn detonate cannot explode twice; a killing detonate reports `detonated`, not `owner_died`). **Origin strings** (who caused a hit or status): `light`, `heavy`, `card:<id>`, `status:<id>`, `relic:<id>`, `enemy`, or "" (tests, scenarios). `EffectContext.origin` carries it into `Health.take_damage` and `StatusEffectManager`; a status tick's origin is `status:<id>`, not the relic that applied it. **On a kill the order is** `hit_landed`, `enemy_killed`, `status_ended(owner_died)`, then the enemy's own died handler.
- **`RelicManager`** ([src/relics/RelicManager.gd](../src/relics/RelicManager.gd)): a child of `RunController`, **not an autoload**, rebuilt every room (each room is a fresh scene) from `RunState.relics` (`RunController._setup_relics`; none is created when relics are off or none held). It applies each relic's `modifiers` to the player's `StatModifiers` (ids `relic:<id>:<n>`) and connects each trigger to the relay. A matching trigger is **queued and run at the end of the frame** (`call_deferred`), because a hit usually arrives inside a physics callback where Godot refuses to spawn an `Area3D` or change a collision flag. `flush()` runs the queue at once (tests). `relic_triggered(relic_id, trigger_index, event_id)` fires when the effect runs. **Recursion guard:** an event whose origin is `relic:*` is ignored unless the filter has `allow_relic_origin`, and chains never go deeper than `MAX_CHAIN_DEPTH` (1); the depth rides with the queued job. **Counters (`every_nth`) and internal cooldowns reset every room** (the manager is rebuilt). Effects roll chances on `player.status_rng`. Inert with no relics (no connections, no `_process`).
- **Data and loaders.** `RelicSchema` (pure; `EVENTS` is the one table of events, their filter keys and whether they carry a position, target or origin, read by the validator and the matcher alike) returns problem strings. `RelicDatabase` loads `data/relics/*.json` (id = file name), `push_error`s and skips bad files; a missing or empty directory means no relics. `RelicConfig` validates and reads the `relics` block of `data/run.json` (`enabled`, `max_owned`, `offer_count`, `relic_room {count, first, last}`, `tier_weights` per act). The relic field is `rarity` (`tier1`, `tier2`, `tier3`, `boss`), because `run.json` `tiers` already means enemy tiers; `boss` is valid only with source `mini_boss`. `sources` is live (`elite`, `relic_room` and, since MAP2, `merchant` decide which room offers a relic; a relic whose `sources` are exactly `["merchant"]` is shop-only); the other accepted values (`mini_boss`, `starter`, `event`, `altar`, ...) and `sacrifice_cost` are reserved for later slices and unused today. `relics.prices` (MAP2) gives a price per tier; boss tier has none and is never sold. `rule_text` (one line, at most 120 chars) and `flavor_text` are required.
- **Offers.** `RelicOffer` is pure (rng passed in): eligible = in the run's pools, lists the source, not owned, not given up this run, weight above 0 for the act; sorted by id, drawn without replacement by tier weight; fewer returned if fewer are eligible. `RunRelics` ([src/run/RunRelics.gd](../src/run/RunRelics.gd)) is the relic half of the choice model (same context dict as `RunChoices`; `RunController` calls `RunRelics.open_for_room`, which hands any other room, or relics off, to `RunChoices.open_for_room`): an **elite** room offers relics instead of cards, and the **relic room** offers relics with no fight; if nothing is eligible the card offer is used. Option ids: `relic:<id>`, `relic_skip` (free, no reject spent), and in the give-up step `giveup:<id>` and `giveup_cancel`. At `max_owned` taking a relic opens the **give-one-up** step (`RunState.pending` = `relic_swap`, `relic_incoming`); Cancel keeps everything; boss-tier relics can't be given up; a given-up relic never returns (`RunState.relics_given_up`). With `relics.enabled` false the run is the old run exactly. On the map the relic room is a `relic_room` node (a relic stage with a chest size) and `rooms.relic_room` in `run.json` is gone. The straight run's relic room is placed by `RunGenerator._place_relic_rooms`: it replaces one combat room (type `relic_room`, `RunConfig.RELIC_ROOM`), never beside the rest room, the elite or another relic room, on its own seeded RNG.
- **RunController API for the UI.** Signals `relics_changed(relic_ids)` and `relic_triggered` (forwarded from the current manager, so the UI connects once). Functions: `relic_manager()`, `relic_offer()`, `relic_swap_state()` (`active`, `incoming`, `giveable`, `owned_count`, `max_owned`), `owned_relics()`, `given_up_relics()` (display dictionaries), `pick_relic(id)`, `skip_relic_offer()`, `give_up_relic(id)`, `cancel_relic_swap()`. All go through `choose`. `RunState` keeps `relics`, `relics_given_up`, `relic_incoming`; `FORMAT_VERSION` stays 2 (old dicts load with empty lists). The save file is `RunSave` (MAP3, see Acts and the save).
- **UI.** `RelicRow` (in `Hud`, under the dodge pips, wraps at the health panel width): a chip per relic, two-letter mark, pool-colour frame; a trigger lights the chip with a name tag, and `RelicFlash` (pure) keeps a burst steadily lit with an "xN" count instead of strobing. `RunOptionCard` draws relic offers (and the free Skip tile); `RunPromptScreen` draws the give-up step (incoming plate, giveable list, a "Cannot be given up" row, Cancel focused by default). `SettingsScreen` lists owned relics on the pause screen (scrolls with Up and Down). `ConditionCue` (pure; MB1 `detonate_short` words a detonate card's slot line, for example Open a Vein's "Wants Bleed stacks") writes the dim "Needs Burn" line on an unlit `CardSlotWidget` and the dodge note on reward cards. Look values: `data/ui.json`; words: `data/run.json` `ui`.
- **Stats relics use** (set by `modifiers`, read by the named code): `card_damage_mult_vs_status.<status>` (`Health.take_damage`, card-origin damage only), `zone_duration_mult` (clamped to the zone cap) and `zone_status_chance` (additive, capped at 1) in `ZoneManager.spawn`; `status_damage_mult.<status>` (BD1); MAP2: `damage_mult` (`Health._source_damage_mult`: multiplies every hit its source deals, before armor, and scales DoT ticks) and `merchant.free_rerolls` (`RunMerchant.free_rerolls`). A modifier may carry `per_run_stat` and `per` (value x floor(stat / per); the only run stat today is `gold_spent_merchant`, listed in `RelicSchema.RUN_STATS`, set by `RelicManager.set_run_stats` from `RunController`). The `hit_landed` event accepts `tag` (Paperwork Fire) and, BD3a, `slot_type` filters. BD3a stats: `status_max_stacks.<id>` and `status_tick_rate.<id>` (read by `StatusEffectManager` from the applier); the basic attacks' interval stats (`stat` per attack in `data/attacks.json`, read by `AttackController.get_interval`; Overtime (Unpaid) uses `attack_interval.light`, and the Warm-Up card buffs `attack_interval.light` and `attack_cooldown.heavy`). Muscle Memory is not a stat: it is a trigger on `hit_landed` running `reduce_cooldown` with `attack_id` `heavy` (`Player.reduce_attack_cooldown` -> `AttackController.reduce_remaining`). The validator floors factor stats at -1. The effect template `reduce_cooldown {slot_type, seconds}` takes time off a running slot cooldown.
- **Bot and capture side.** `RelicPolicy` (`src/debug/`) picks relics for the wave sim (the first offered whose keyword is carried by at least 3 deck cards, else the first; at the cap gives up the first giveable; draws no random numbers). `RelicArgs` parses the launch flags; scenarios may set a `relics` list (an arena `RelicManager` on the host). Details of the commands: `README.md`.

### Statuses ([src/combat/StatusEffectManager.gd](../src/combat/StatusEffectManager.gd), `StatusDatabase`)
A `StatusEffectManager` node on every body that can be affected. `StatusDatabase` validates `data/statuses.json` once; a bad entry is treated as missing and `push_error`s. Effect types are closed (`StatusDatabase.EFFECT_TYPES`): `damage_over_time` (Burn, Bleed), `heal_over_time` (Regeneration), `lifesteal` (Leech: a fraction of damage dealt, with a per-hit cap, counted after resistance and skipped at full HP) and `stun`. Visual kinds (`VISUAL_KINDS`): `flame`, `stars`, `drips`, `ring`, `orbs`. Stun has diminishing returns and per-rank multipliers (`StunRules`; elite half, boss immune). Signals: `status_applied/expired/refreshed/resisted`. Burn flames and stun stars come from `EffectPool`; Bleed, Regeneration and Leech cues are held nodes (one, one and two) so they stay inside the pool budget. Burn and Bleed share the HP bar's single pip slot, alternating.

**Stacking and detonate (BD3a).** A damage-over-time status may carry `stacking {max_stacks}` in `data/statuses.json` (validated by `StatusDatabase._validate_stacking`; shipped Bleed has none, so its cap is 1). The effective cap is the data cap through the **applier's** `status_max_stacks.<id>` stat (`StatusEffectManager.max_stacks_of`; Bad Influence and Serrated Excuse raise it), taken from the latest applier. A reapply adds a stack only below the cap, and stacks left above a cap that later drops stay until the status ends. Damage per tick scales with stacks, and the tick interval is divided by the applier's `status_tick_rate.<id>` (re-read each tick, floored at 0.1 s). `status_applied` does not fire on a stack gain: `status_stacks_changed(status_id, stacks)` does. `detonate_status(status_id, multiplier, source, origin)` pays the remaining ticks at once and removes the status (reason `detonated`); `status_detonated(status_id, amount, stacks)` is its signal. `StatusStackLabel` (a child of `EnemyHpBar`, signal-driven, from 2 stacks) shows "Bleed xN" or "MAX" and plays the detonate cue (enlarged number, burst ring, "Bleed detonated"; MB1: the word stays clear of the number and labels lift clear of one another on screen, `StatusStackLabel.lift_over`, keys `detonate_word_clamp_extra`, `detonate_word_above_number`, `overlap_pad`, `lift_speed`); texts and sizes are `data/ui.json` `status_stacks`. It is built inside a deferred call on purpose: passing a pre-built node through `call_deferred` leaked it (71 orphans) or logged an engine ERROR when the enemy freed first.

### Attacks (light and heavy)
`data/attacks.json` -> `AttackDatabase` (validated) -> `AttackController` (pure timing: cooldown, auto-fire only with a target, click-rate cap as a ratio, wind-up). `Player._on_attack_fired` runs the same `cone` (or `aoe` for targeted heavies, or `projectile` for a bolt light) template cards use, then `AttackStatuses.apply_on_hit` (on-hit statuses, element chance), then `Juice.hit_stop` and shake. `light` is the default light attack (the Rogue's arc). The optional `light_variants.<name>` holds others (W1a: `wizard`, shape `projectile`, with an optional `bolt_look` {color, scale} for the bolt's own look). The heavy is `heavy.<id>`. Which variant and heavy a character uses is `attacks.light` / `attacks.heavy` in its `data/characters.json` entry (`CharacterDatabase.light_variant`, `heavy_class`); `AttackDatabase.load_valid(class_id, light_variant)` loads them. The heavy meter's word (SWING or CAST) is data: `ui.json` `hud.meter_windup_words`, by attack shape.

### Enemies and spawner
- `Enemy` ([src/enemies/Enemy.gd](../src/enemies/Enemy.gd)) is one script for all types. `_apply_stats` overrides the scene's exported values with `data/enemies.json` `enemies.<id>.stats`. It chases, telegraphs (ground wedge or shot lane), then attacks through `EffectTemplates` (cone for melee, projectile for ranged). Separation steering uses a static roster and `spawn_index`. Signals: `stunned`, `stun_ended`, `stun_refreshed`.
- Types: `melee_chaser`, `ranged_shooter`, `fire_resistant_golem`, the boss `boss_guardian` and (MB1) the mini-bosses `boss_brute` and `boss_duelist` (scenes in `scenes/enemies/`, ids and rank in `data/enemies.json`; the bosses are their own section).
- `EnemySpawner` runs a `WavePlan` built from `WaveConfig` (`data/waves.json`): staged groups, a delay per stage, a `max_alive` cap, ring spawn positions, spawn attack grace. A table with `finite: true` ends after its last stage (endless ones loop), and `EnemySpawner.room_cleared()` is true when a finite plan is done and nothing is alive. A queued spawn is the enemy id, or `"<tier>|<enemy id>"` for an elite or boss (`WavePlan.TIER_SEPARATOR`), which keeps the shuffle's random calls identical to the plain-id case. Signal `enemy_spawned(enemy, alive)`. `set_seed` seeds spawn choices.
- `EnemyConfig` validates `data/enemies.json` (call `validate_stats`; `Enemy` reads via `stats_for`, `rank_for`, `scene_path_for`).
- **Pressure knobs (H1):** the `pressure` block holds shared multipliers, read through `EnemyConfig.speed_scale()`, `attack_rate_scale()` and `telegraph_scale()` and applied in `Enemy._apply_stats` (move speed times `speed_scale`; attack cooldown divided by `attack_rate_scale`; telegraph duration times `telegraph_scale`, added in H3 and including the boss's adds). `EnemyConfig.validate_pressure` requires the first two, `telegraph_scale` is optional, each 0.25-4.0, and rejects unknown keys. They scale normal and elite enemies and the boss's adds; the boss itself is not scaled (its speeds are in `data/bosses.json`). Values: see `data/enemies.json`. The future difficulty tiers reuse them.

### The boss (Milestone 3c)
- **Data:** `data/bosses.json` -> `BossConfig` ([src/enemies/BossConfig.gd](../src/enemies/BossConfig.gd), validator; a bad file is a `push_error` and no boss exists). `rules` (minimum telegraph, maximum transition (stagger plus roar must fit inside it; the validator rejects a total over it), adds cap, minimum attacks), then per boss id (a key of `data/enemies.json` with rank `boss`): name, HP, `resistance` (applied to every element), `knockback_taken`, `transition` (`stagger` optional, default 0.8 s, 0 = no stagger; `BossConfig.stagger_seconds`; plus `duration`, `shake`, `hit_stop`, `ring_size`), `death`, `attacks` and `phases` (HP threshold `enters_at`, speed, attack gap, wind-up scale, optional `summon`, weighted attack list). Numbers live there, not here.
- **Rules:** `BossRules` ([src/enemies/BossRules.gd](../src/enemies/BossRules.gd)) is pure: which phase an HP fraction is in, attack picking, telegraph sizes (from `VfxSizing`, the same numbers the hit queries use) and `escape`, the fairness check (`escape`) that an attack can be walked or dodged out of; only a test applies it. `tests/unit/m3c_boss_test.gd` covers it.
- **Brain:** `Boss` ([src/enemies/Boss.gd](../src/enemies/Boss.gd), extends `Enemy`, group `boss`; scene `scenes/enemies/BossGuardian.tscn`) is a state machine: chase, wind-up (telegraph), active, recover, stagger, transition (the roar), dead (`Boss.State`). Attacks go through `EffectTemplates` (cone, aoe, projectile with `yaw_degrees`); telegraphs are drawn at the vs-player reach. Not solid while charging (and solid again only once clear of the player). `boss_guardian` is unstunnable and takes no knockback; a mini-boss (MB1) has rank elite, so a stun works on it (see Mini-bosses below), and any boss ignores knockback during a wind-up or an active attack. Phase thresholds are held by `Health.hp_floor`; each crossing first runs a **stagger** (D16: the current attack is dropped, the boss reels with a tint and tilt, and the floor drops to the next threshold so the player's hits count; one hit cannot pass two thresholds, and the stagger into the last phase keeps a 1 HP floor), then the invulnerable roar, then `phase_changed`. Adds (`summon`) are capped and killed on its death. The death beat (slow-mo, then the win) counts game time when hit-stop is off.
- **Signals:** `phase_changed`, `stagger_started(next_phase_index, duration)` / `stagger_ended(next_phase_index)` (`Boss.is_staggered()` between them; `stagger_ended` fires as the roar begins), `transition_started/ended`, `attack_telegraphed(id, label, windup)`, `attack_landed`, `adds_summoned`, `defeated`. `RunController.boss_spawned(boss)` fires when it spawns; `current_boss()` returns the living boss or null.
- **Spawning:** the boss room in `data/run.json` spawns `boss_guardian` like any enemy; it has no tier. Unlike other enemies it spawns inside an on-screen box (PL2): the optional `spawn` block of `boss_guardian` in `data/bosses.json` (`distance_min`, `distance_max`, `screen_half_width`, `screen_up`, `screen_down`; meters). `EnemySpawner._boss_spawn_position` tries ring points in that box (16 random tries, then a sweep of `BOSS_SWEEP_ANGLES` (72) angles at three distances, then the plain ring); `EnemySpawner.screen_box_contains` does the isometric math for the camera in `scenes/camera/CameraRig.tscn`, and `tests/unit/boss_spawn_pl2_test.gd` pins the box to that rig. Retune the box if the camera changes. Other enemies keep the plain ring.
- **Mini-bosses (MB1, D44 = C; design note `docs/MAP.md` section 11):** a `data/bosses.json` entry with `"mini_boss": true` (`BossConfig.is_mini_boss(enemy_id)`) is a mini-boss: `Boss` gives it status rank elite (stunnable: a stun cancels the wind-up and lasts half as long; `boss_guardian` stays immune), a 1.0 s death beat (`death.beat_seconds`), and its death ends the act, never the run. Final HP is `max_health` x `run.json` `acts.N.hp`, with no tier multiplier. Act 1 is `boss_brute` "Head of Facilities" (slow, armor and resistance in the data, 3 phases, `melee_chaser` summons in phases 2 and 3); act 2 is `boss_duelist` "The Corporate Raider" (small, fast, 2 phases, no adds). Numbers: `data/bosses.json`.
- **Boss attack data added in MB1:** aoe `count` / `scatter` (several discs per cast, a victim is hit once per cast; the telegraph is compact; `BossRules.escape` handles multi-disc); `chain` (the id of the attack that winds up straight after this one: at most 2 attacks, no cycles, and a chain-only attack gets no weight, so `BossConfig.weighted_attack_ids` leaves it out of picks and the "minimum attacks" rule); `kind: "blink"` (no damage; a cyan landing marker with a ghost; the landing is `BossRules.blink_landing(boss_pos, player_pos, behind, limit, min_gap)`, clamped to the arena). Example: the Raider's Leveraged dash chains to `leveraged_dash_2`, and Golden parachute chains to Backstab.
- **Mini-boss bar (BD3a):** `MiniBossBar` ([src/ui/MiniBossBar.gd](../src/ui/MiniBossBar.gd)) is a child of `BossHpBar`, in the boss bar's spot (a mini-boss room has no boss). **Since MB1 the act mini-bosses are real bosses (`Boss`, see "Mini-bosses" below) and use `BossHpBar` itself; `MiniBossBar` is now used only for enemies with tier `mini_boss` (kept for MAP4).** It scans the world at 4 Hz for an `Enemy` whose tier is `mini_boss` (the tier is applied a moment after spawn and `Enemy` has no signal for it) and follows the first one alive, handing over to the next. It draws a name row, the boss meter and the armor and resistance words, with no phases and no attack line (those are MB1's). The name is data: `data/run.json` `tiers.mini_boss` `name_format` ("Act %d Mini-boss") and `display_name`. `BossHpBar.occupied_bottom()` counts it for the damage numbers' keep-clear band. The elite and boss markers (`TierMarker`) take their size from `tiers.<id>.marker_size`; the mini-boss's is the same as the boss's.
- **UI:** `BossHpBar` (a `CanvasLayer` in `Main.tscn`) finds the boss by class on `node_added`, so it also works in the capture scenarios, and reads the boss's live state on bind (a reload mid-fight starts correct). It draws a `BossMeter` (fill, ghost, threshold notches and lines, invulnerable stripes, resist frame). In the stagger it shows a STAGGERED cue and the phase line reads "Hit it now" (`boss_bar.stagger_*` keys in `data/ui.json`); the notch counts as crossed from the stagger start; "Invulnerable" shows only in the roar and a `BossAttackStrip` (attack label and draining wind-up strip). MB1: a mini-boss shows a subtitle "Act N Mini-boss" (`BossHpBar.subtitle_text`, the act read once at bind through `ActTint.act_of`, so it cannot say Act 2 behind the Act 2 screen) and the attack line adds "(1/2)" / "(2/2)" for chained attacks (`BossHpBar.chain_step`, read from the data `chain` field; format `boss_bar.chain_format`); sizes `boss_bar.subtitle_height`, `subtitle_font_size`, `subtitle_whiten`. `BossHpBar` is in group `boss_hp_bar` and `occupied_bottom()` gives the bottom edge of the bar block (0 when hidden); `DamageNumber` uses it to keep numbers below the bar (`data/ui.json` `damage_numbers.boss_bar_gap`). Placement: `HudLayout.boss_bar_rect` (top centre); `HudLayout.debug_overlay_top` puts the F3 overlay below it; the room indicator is top right. Look and sizes: `data/ui.json` `hud.boss_bar_size`, `hud.debug_overlay_gap`, the `boss_bar` block; boss lane alpha: `data/vfx.json` `boss_lane_alpha`.

### Effects and VFX
`EffectPool` (one per world, found with `EffectPool.for_world`) animates simple primitive effects (disc, wedge, sphere burst) with a cap from `data/vfx.json` `max_simultaneous`; at the cap the oldest is recycled. `TemplateVfx` draws each template's visual (`enemy_shot_lane(..., boss, ramp)`: with `ramp` true, the boss volley's lanes brighten from the start alpha to the end alpha across the wind-up, length capped by `boss_volley_lane_max_length`); `VfxSizing` derives visual size from the hit numbers so visuals equal hitboxes. `ElementVisuals` maps a damage type to color/scale from `data/pools.json` `visual`; a team tint (`data/vfx.json` `team_tints`) makes enemy shots pink.
- **Buff aura (PL3):** `TemplateVfx.buff_aura(pool, target, cue, duration)` draws a pulsing ground ring and a faint bubble that follow the target while a buff lasts. The `buff` template calls it (`EffectTemplates`) with the cue for the buffed stat: `data/vfx.json` `buff_cues` (keyed by stat; today only `armor`, the Ward), read through `VfxConfig.buff_cue(stat)` and checked by `VfxConfig.validate_buff_cues`.
- **Volley safe gaps (PL3):** the Fan of regrets telegraph tints the space between two lanes only where a gap is really clear. `VolleyGaps.segments` / `first_safe_distance` compute it (clear half width = `r * sin(delta/2) - lane half width`); `TemplateVfx` draws it using the `boss_volley_gap_*` keys in `data/vfx.json` (color, `min_half_width`, `segment_length`, `alpha_start`, `alpha_end`). Up close there is no gap, only the dodge helps.

### Acts and the save (MAP3)
Plan: `docs/MAP.md` sections 4.5 and 8; calls: DECISIONS "MAP3 split", "MAP3 sitting A calls", "MAP3 sitting B calls", "MAP3 ux calls". Shipped: 3 acts of 10 rooms (30 rooms). `data/map.json` `acts` is the count; 1 plays as MAP2 (the last room is the boss), and the debug flag `--acts=N` overrides it (`MapLaunch.resolve_acts`, `RunSession.acts_override`; exit 2 on a bad or repeated value, range 1 to `RunState.MAX_ACTS`).
- **Acts in `RunState`:** `act`, `acts_total` and `past_acts` (`[{map, path}]` per finished act). `map`, `path` and `room_index` always describe the current act, so older code keeps working; `act_map(n)` and `act_path(n)` answer for any act. `rooms_per_act()`, `run_room_number()` and `run_room_total()` count over the whole run. All of it is in `to_dict`/`from_dict` (`FORMAT_VERSION` is still 2; an old dict loads as act 1 of 1).
- **Per-act maps:** `RunNodes.advance_act` moves the finished act into `past_acts`, generates the next map (`MapGenerator.generate(seed, ..., act, acts_total)`, seeded from the run seed and the act through `RunState.act_seed`) and opens the pick. HP, gold, deck, relics and rejects carry over. **D45 = B (BD3a):** `RunController._apply_act_start_heal` heals `run.json` `acts.start_heal` x max HP (capped at max; 0 or a missing key = none) when act 2 or 3 starts, before the act's first autosave. `act_summary()` carries `hp_before`, `hp_after`, `healed` and `heal_fraction`; a run resumed from a save reports `healed` 0 (the heal is already in the saved HP). `map.json` `multi_act` holds the rule changes that apply only when `acts` is above 1 (`path_rules.relic_route`, `max_relic_rooms`, `estimate.merchant_prices`).
- **Random streams:** act 1 uses `room_index` as the stream position, so a one-act run is unchanged; later acts use `RunState.stream_index()` = `room_index + ACT_STRIDE * (act - 1)`. Offers, spawns and gold must use `stream_index()`, not `room_index`.
- **Mini-boss:** room 10 of acts 1 to `acts_total - 1` is a `mini_boss` node (type id `mini_boss`, "MB" in `MapGraph`); room 10 of the last act is the boss. Encounters are `data/run.json` `rooms.mini_boss` (`mini_boss_act1` spawns `boss_brute`, `mini_boss_act2` spawns `boss_duelist`, one spawn each, no adds in the room; `acts` field picks the list; see "Mini-bosses (MB1)" in the boss section). `tiers.mini_boss` is no longer used by these two (kept for MAP4); its gold is `gold.mini_boss`. Interim reward (until MAP3b): gold, a normal relic offer at the next act's tier odds, then a normal card offer.
- **Act scaling:** `data/run.json` `acts` = `{"<n>": {hp, damage, gold, tint}}` (validated in `RunConfig`; absent = x1; MB1 `tint` = `{floor, light}` colours, applied by `ActTint` ([src/run/ActTint.gd](../src/run/ActTint.gd): `apply(arena, act)` copies the Floor material and sets the Sun colour, `act_of(arena, fallback)` reads the act back from arena meta so the boss bar and scenarios need no `RunController`)). Values were set by the run sim. Wave lists carry an `acts` field (act 1 keeps the old lists).
- **RunController:** `current_act()`, `act_count()`, `act_label()`, `run_room_number()`, `run_room_total()`, `run_room_label()` (use it, not `room_label()`, on multi-act runs), `act_summary()` and the signal `act_started(act, summary)`. It fires when the next act's map is made, in the same call that opens the pick; it does not fire when a save is resumed at an act's first map.
- **UI:** `ActText` (pure: "Act 2 of 3", "Room 14 of 30"; words in `data/run.json` `ui.act`), `ActScreen` ([src/ui/ActScreen.gd](../src/ui/ActScreen.gd), layer 12; opens on `act_started`, holds the map pick until Continue, swallows fight keys; BD3a: a heal line from `ActText.heal_line`, hidden when `healed` is 0, and the HP in red with a "Running low" tag (`ui.act.low_hp_tag`) below `ui.act.low_hp_fraction`), `RunHud` shows a two-line plate on multi-act runs, `RunTypeIcon.coin` draws the merchant's coin on the legend, HUD plate and shop title. Sizes: `data/ui.json` `hud.room_indicator_size_acts`, `run_ui.shop_scroll_slack`.
- **The save:** `RunSave` ([src/run/RunSave.gd](../src/run/RunSave.gd)) is static, one slot: `user://run_save.json` (`{save_version, run}`; `SAVE_VERSION` 1), written through a temp file. `autosave` runs at the map screen and at each room start (`RunController`), never before the first room of act 1 and never for straight runs. Deleted on a win or a loss (`delete_save`). `has_save()` and `load_save()` (makes the saved run the live one; the caller starts the scene) feed Continue on `ClassPickScreen`; `summary()` is the text it shows. A bad, old or unreadable file is ignored with a warning (`RunSave.last_problem`) and left on disk. `from_dict` validates types, relic ids, overlap and the cap, and clamps negative gold. BD3a: `_state_problem` refuses a save whose `hp` is NaN, at or under 0 or above max, whose `rejects_remaining` is outside 0..`rejects_per_run`, or whose `removed_cards` holds a non-string, empty or unknown id (a missing key reads as empty; `SAVE_VERSION` and `FORMAT_VERSION` are unchanged). A straight run's win or loss deletes the save only when it owns a map run. **Never touched** in headless runs, `-s` scripts, or a launch with a debug flag (`DEBUG_FLAG_PREFIXES`: `--run-room`, `--run-node`, `--acts`, `--deck`, `--scenario`, `--sim-` ...). Tests set `RunSave.persist_override = true` and a `user://tests/...` `path`, then call `RunSave.reset()`. Resuming mid-fight restarts the room.

Used by `CardSlotWidget` (active card frame and next-up swatch), `RunOptionCard` (reward offers and removal cells). The reject tile keeps its own border. The slot "ready" cue is a plate and text brightness, not the border. Look keys are in `data/ui.json` (`hud.slot_frame_*`, `slot_plate_*`, `slot_next_swatch_width`; `run_ui.option_frame_width`, `option_card_focus_color`).
- **Melee reach cue (PL2):** `MeleeReachCue` (`src/ui/MeleeReachCue.gd`, attached to the player by `Main`) draws a faint arc at the light attack's reach when no enemy is in reach, and brightens it on a whiffed click. It is keyed on the light attack's `arc` shape, so the Wizard (projectile light) never shows it, and it creates its band only when armed. Look: `data/ui.json` `melee_cue`.
- The class pick screen hides the HUD while it is open (PL2).
- **Key labels (K1, director decision in GDD section 3):** UI key text is never typed into code or data. [src/core/InputLabels.gd](../src/core/InputLabels.gd) is a static `RefCounted` that reads the live `InputMap` and `data/slot_types.json` on every call and caches nothing.
  - `for_action(action)` gives "Q", "Shift+Q", "LMB", or "?" when unbound. `slot_name/slot_key/slot_label/slot_swap_key` take a slot type; the `_at(i)` variants take the HUD index (`CardSlotController.SLOT_TYPE_ORDER`). `slot_label` gives "Recovery (R)". Physical keycodes are shown as the player's layout names them (headless shows the physical key).
  - `InputBindings.bindings_changed` fires after each `load_bindings`. `Hud` (slot hints, `AttackMeter` labels, `DodgePips`; layout rebuilt via `_apply_layout`) and `SettingsScreen` listen to it. Text that is built when a screen opens (reward and removal cards, `RunOptionCard.slot_now_text`) just calls InputLabels at that moment. Widths for key labels: `HudLayout.key_label_width`.
  - Templates take the label as an argument: `data/run.json` `ui.option` (`slot_now` "In slot: %s" since PL3, `slot_key` "%s", `slot_label` "%s (%s)"), `data/ui.json` pause hint "%s also resumes". Fixed menu keys (Enter, arrows, class-pick 1/2) may be named on screen (D26).

Plain R and Shift+R are not a conflict. `InputBindings.load_bindings` calls it and `push_error`s each conflict; the game keeps running, and tests read `InputBindings.last_conflicts`.
  - **Enforced by tests:** `tests/unit/k1_key_hint_scan_test.gd` scans `src/*.gd` string literals and `data/*.json` values and fails on a hardcoded slot, mouse or modifier hint ("Slot %d", "1-5", "Shift+", "LMB", "Press Space"...). Other K1 tests: `input_labels_test.gd`, `k1_ux_test.gd`, `k1_qa_test.gd`.

- `EnemyHpBar` is a billboard per enemy using `assets/shaders/enemy_hp_bar.gdshader`; visibility mode is `data/ui.json` `hp_bars.visibility_mode`.
- `GameOverScreen` (listens to `Main.game_over_ready`; shows the run line in run mode), the run UI (see Run flow), `SettingsScreen` (Esc; one setting; calls `GamePause`), `DebugOverlay` (F3), `AimIndicator`.
- All UI numbers, colors and strings go through `UiConfig` (`data/ui.json`), which validates the `hp_bars`, `death_beat`, `aim`, `popups` and `damage_numbers` blocks on load (others are read as is: unverified).

## 5. Data flow: card key to applied effect

1. Input event (`slot_N`) reaches `Player._unhandled_input` (only if no UI screen consumed it).
2. `CastInput.press/release` decides, from `Settings.casts_on_release()`, whether this event is a cast; the slot index is queued (`_cast_queue`).
3. Next physics tick: `Player._handle_card_slot_input` -> `CardSlotController.try_use(slot_type)`.
4. `CardSlot.use_card` checks the slot is ready, discards the card, starts the cooldown (with `StatModifiers`), and draws the next card. Returns "" if cooling, which stops the cast.
5. `CardSlotController._cast_card` builds an `EffectContext` (BD1: with the cast history and clock) and, for each entry in the card's `effects` array, calls `EffectTemplates.execute(template, params, context)`. `execute` first checks the effect's `condition`: a caster condition (`cast_within`, `zone_active`) skips the whole effect; a target condition filters the hurtboxes the hit path found.
6. Template runs: cone/aoe query hurtboxes and call `Hurtbox.receive_damage`; projectile spawns `Projectile.tscn` (damage lands later); dash calls `Player.start_forced_move`; heal/buff touch `Health`/`StatModifiers`; apply_status calls `StatusEffectManager.apply_status` on `context.last_hits`.
7. `Health.take_damage` -> armor (physical, neutral) or resistance (elemental) -> `damaged`/`died` signals -> owner calls `Juice.on_hit_landed` with the channel -> damage number style (plain, `[armor]`, `<resisted>`).
8. `CardSlotController.card_cast` is emitted and `CombatEvents.notify_card_cast` records the cast (BD1); consumed primes are used up from a snapshot taken before the cast. The HUD shows the new cooling state, glow and primed marker next frame.

Light and heavy attacks skip steps 2-5 but share steps 6-7.

- `RunController.act_started(act, summary)` -> `ActScreen` (and `MapScreen`, which holds its pick until the act screen closes).
- `Health.damaged / healed / health_changed / died`.
- `CardSlotController.card_cast(slot_type, card_id)`; the `CombatEvents` relay signals (BD1 `card_cast`; BD2 the rest, listed in section 4, Relics). `RunController.relics_changed(relic_ids)` and `relic_triggered(relic_id, trigger_index, event_id)`; `RunController.gold_changed(total, delta)` (a fight payout is positive, a merchant purchase negative); `RelicManager.relic_triggered` (same args).

## 8. How to add things

### A card
1. Add `data/cards/<pool>_<name>.json` with the fields above. `slot_type` must be in `slot_types.json`, `pool` in `pools.json` (its `frame_color` sets the card's frame), each effect `template` in `EffectTemplates.REQUIRED_PARAMS` with all its required params.
2. Names over `ui.json` `hud.name_warn_length` raise a warning (HUD shrinks/truncates).
3. Attack cards must beat the free light attack (`CardDamageRule`); a load check and a test fail if not.
4. Run the tests (`card_database_test`, `starter_card_set_test`, `card_schema_test` load real data). A new card is not in a character's 15-card `starting_deck` (`data/characters.json`); it appears only as a reward unless added there (or via `--full-deck`). A card also changes unique counts: the deck rules (`deck_rules.json`) must still pass (`DeckRules.validate_shipped_content`).
5. A card is only reachable if its pool is in the character's `pools` (`data/characters.json`; `Player.owned_pools` is filled from it).
6. A card is in a starter only if listed in that character's `starting_deck` in `data/characters.json`.
7. (BD1) Tags are derived: don't write them. A Keystone/Primer/Payoff card lists them in `keywords`. A conditional payoff is an extra effect with a `condition` placed before the effect that sets the status; keep an unconditional damaging effect on the card (the damage rule skips conditional ones). **Any new pool card moves the seeded sim hashes**, because the arena player and the bot sim fill slots from every owned card; rebaseline and say so (README, Last verification).

### A keyword or a condition type
Keyword: add it to `data/keywords.json` (name capitalised, not a derived tag), no code. Condition type: add the id to `EffectCondition.TYPES`, a branch in `validate`, `caster_ok` or the per-target hit paths, a line in `SlotSynergy.condition_live` and the text in `CardSummary`, and tests (`tests/unit/bd1_*_test.gd` show the pattern).

### A relic (BD2)
Add `data/relics/<id>.json` (fields in section 6). No code if it only needs the existing stats, events and effect templates: `modifiers` use any stat name; `triggers` pick an `event` from `RelicSchema.EVENTS` and only its listed filter keys; `effects` are normal effect templates; `at` is `player`, `event_position` or `event_target` (an aoe lands at the event point, a zone at the event point clamped by its `max_range`, a projectile or dash ignores `at`). `pool` must exist in `pools.json`; `sources` decide which room offers it (`elite`, `relic_room`, `merchant`; exactly `["merchant"]` makes it shop-only, and its tier must have a nonzero weight in the act or it is never stocked; `tier3` never appears while act 1's weights are 80/20/0); keywords are free text for the offer chip and the bot's archetype match; `rule_text` is the one-line rule shown on the HUD tooltip, the offer and the pause list. A relic that applies a status and one that reacts to it need `allow_relic_origin` on the reacting trigger, or the guard ignores it. A new stat needs a reader in code (see "Stats relics use"); a new event needs the relay signal, a `notify_*` call at the source, an `EVENTS` entry and a handler in `RelicManager._handler_for`. Run `RelicSchema` through the tests (`bd2*` suites load the shipped relics).

### A character (class)
Add an entry in `data/characters.json` (fields in section 6); `CharacterDatabase.validate_table` checks it. Give it a class pool in `data/pools.json` (with a `frame_color`) and its cards in `data/cards/`. A new light shape or heavy goes in `data/attacks.json` (`light_variants` / `heavy.<id>`). The class pick screen lists the characters from the database. A preset deck names its class with `"class"`.

### An enemy
1. Duplicate a scene in `scenes/enemies/` (root script `Enemy`), set `enemy_id`, mesh, `Hurtbox` team "enemy", resistances on `Health`.
2. Add `enemies.<id>` in `data/enemies.json` with `rank` (normal/elite/boss), `scene`, and the full `stats` block (`EnemyConfig.validate_stats` lists required keys).
3. Reference the id in `data/waves.json` stages.

### A status
Add an entry in `data/statuses.json` using an existing `effect_type` (`damage_over_time` or `stun`; a stackable damage-over-time status adds `stacking {max_stacks}`, and a card or relic raises the cap with a `status_max_stacks.<id>` buff) and a visual `kind` (`flame` or `stars`). Visual kinds are `flame`, `stars`, `drips`, `ring`, `orbs`. A new effect type or visual kind needs code in `StatusDatabase` (`EFFECT_TYPES`, `VISUAL_KINDS`), `StatusEffectManager` and the cue drawing. Apply it from a card with `apply_status`, or from an element via `pools.json` `status`.

### An effect template
(`detonate_status` in BD3a is the worked example of a whole new template: `REQUIRED_PARAMS`, a validator, an `_execute` case over `last_hits`, a `StatusEffectManager` method and signal, and text in `CardSummary`.) (For a new option on an existing template, extend `EffectTemplates.validate_params` and its header comment instead.) Add the id and required params to `EffectTemplates.REQUIRED_PARAMS`, add a case in `execute` and an `_execute_<name>`, add its VFX in `TemplateVfx` (sized through `VfxSizing`), add a preview shape if it has a hit area (`CastPreviewShapes`, `CastPreview`), and cover it in `tests/unit/effect_templates_test.gd`.

### An element
Add a pool in `data/pools.json` with `kind: "element"`, a `frame_color`, a `visual` (color, scale) and optionally a `status`. Cards use the element id as `damage_type`. No code is needed for the look (`ElementVisuals`); a test proves a Water entry works.

### A slot type
`SLOT_TYPE_ORDER` in `CardSlotController` and `USE_ACTIONS`/`SWAP_ACTIONS` in `Player` are hardcoded to five. A new slot type needs code plus HUD and input binding changes, not just data.

### A room wave list or room type
Add a variant under `data/run.json` `rooms.<type>` with `id`, optional `min_index`/`max_index`, optional `acts` (MAP3: a list of act numbers that may use it; no `acts` = every act), `first_wave_delay` and `stages`. A mini-boss encounter is a `rooms.mini_boss` variant (`acts` picks act 1's or act 2's); since MB1 its spawn is a `mini_boss: true` boss id from `data/bosses.json` (older MAP3 variants used `"tier": "mini_boss"`). `RunConfig.validate` checks enemy ids and that every room index has a variant; the run tests load the real file. A new room *type* also needs `composition`, `RunController` handling, an icon in `RunIcons` and a `run_ui` colour.

### A map node type or chest size (MAP1)
Types are in `data/map.json` `types` (weight, room window, `no_repeat`; weight 0 means defined but never drawn); `MapConfig.NODE_TYPES` lists the accepted names and `RELIC_TYPES` (code) the relic-counting ones. A type that starts a fight also needs a wave list under `data/run.json` `rooms.<type>`, a `gold` range, and a name and hover text in `run.json` `ui` (`type_names`, hover templates). A drawn type with no node handling is code in `RunController` / `RunNodes` / `RunChoices.open_for_room` (the merchant, MAP2, is the worked example: `RunMerchant`). Changing the rest or merchant weights can break `min_rest` or the relic estimate: run the sweep. A chest size is an entry under `map.json` `chests` (all three sizes are required once the block exists). Check with `tools\run_map_print.ps1 -Sweep 1000` (exit 1 on a failure) and the `map1*` tests.

### A reward rule or choice
Card reward filtering is data: add `requires` to a card (`slot_types`, `pools`, `status_sources`) and `RewardOffer` applies it. Weights, offer size and which room types reward are `data/run.json` `rewards`. A new kind of option (for example a level-up pick) is a new branch in `RunChoices.options`/`apply` plus an option `kind` and a `RunOptionCard` look; the screen is otherwise generic. Wording lives in `run.json` `ui`.

### A boss attack, phase or boss
Attack: add it under `attacks` in `data/bosses.json` with an existing `kind` (cone, aoe, volley, charge; see the `BossConfig` header) and list it in a phase's weighted `attacks`; `BossConfig.validate` rejects malformed entries (including a telegraph under `rules.min_telegraph`); a test (`m3c_boss_test`, `BossRules.escape`) checks every shipped attack can be walked or dodged out of. A new attack kind needs code in `Boss`, `BossConfig` and `BossRules` (unverified in detail). A phase is one more entry in `phases` (descending `enters_at`). Another boss: add `bosses.<id>` with a matching `enemies.json` entry (rank `boss`) and a scene using the `Boss` script; the bar reads the name and phases from the boss.

### A debug preset deck
Add `data/debug_decks/<name>.json` (`name` = the file name, `description`, `full`, `starter`; see section 6). No code. Check it with `godot --headless --path . -- --list-decks` (a broken file prints `INVALID` and exits 2). A new card is not in any preset until you add it.

### A scenario
Add an entry in `data/scenarios.json`; unknown or misspelled keys fail on load (`ScenarioSchema`). Add a test in `tests/unit/` if it proves behavior. Document the new scenario in `README.md`.

## 10. Known sharp edges

- **Projectiles leave `last_hits` empty** (damage lands later). An `apply_status` after a `projectile` in the same card hits nothing.
- **Seeded sims repeat exactly** only at `--fixed-fps 60` with hit-stop off (what `run_wave_sim.ps1` does at `-Scale 1`), on one machine and build. A new RNG or wall-clock read in gameplay breaks this; seed it through `Player.default_rng_seed` or the shared RNG, and `seeded_sim_repeat_test` will fail.
- **Only `GamePause` should set `paused`.** The pause screen and cast preview run `PROCESS_MODE_ALWAYS`. The pause also freezes `Juice` time scale and hands the remaining hit-stop/slow-mo back on resume.
- **Autoload state survives a scene reload** (`Engine.time_scale`, `Juice`, `GamePause`). `Main._prepare_for_restart` resets them; anything new that is global must be reset there too. Re-run the reload soak after touching `Main`, `Juice`, `Player` or the autoloads.
- **Dodge tests and `DodgeSwitch`.** The dodge shipped off in H2 and is on again since H3. Older suites still call `DodgeSwitch.enable()` (`tests/support/dodge_switch.gd`: switch on, test-only key F9 on the `dodge` action) in `before_test` and `DodgeSwitch.reset()` in `after_test`; it is no longer required for the shipped config.
- **Game over arms after a delay.** `GameOverScreen` ignores Try again for `run_ui.prompt_option_arm_delay` after it shows (`is_armed()`), and swallows Space (it was the Movement card key in the H2 trial; the dodge is on Space again since H3). The hint reads "Enter".
- **Dodge distance is data** (`data/player.json`, speed x duration). The `Player.gd` and `PlayerConfig.gd` fallbacks must match it; they are used only if the file is missing or bad. Dash cards use their own `distance` and `speed`.
- **Solid enemies change difficulty and tests.** `body.collide_with_enemies` roughly doubled HP lost in the sim. A crowd can pin the player (the wave sim's `pinned:` line watches it). Lunge stops at the first body. Keep `WorldRef` in mind: use `WorldRef.get_world(tree)`, not `current_scene`, for anything that spawns into the arena.
- **Pass-through leaves a timer alive** for about one object per reload until it expires (qa N2).
- **The Lunge preview** shows the full path even when a body will stop the dash short (known gap).
- **Hit-stop only on `KIND_HIT`.** A new damage source that should feel heavy must pass `Health.KIND_HIT`; DoT and zone ticks use `KIND_DOT`.
- **New `class_name` scripts** aren't picked up by a plain headless test run: run `godot --headless --editor --quit --path .` once.
- **Sims must run as scenes** (not `SceneTree` scripts) or autoloads won't exist.
- **Shift+key** is a swap, not a cast. Ctrl is the Movement slot key (H3), and the slot keys still cast while Ctrl is held; Movement's swap is Shift+Ctrl, and `Player._swap_by_late_modifier` handles Shift pressed after Ctrl is already down (and Alt) by checking the swap bindings. Slot keys use `exact_match` on press so Shift+Q doesn't also press Q. The slot keys are Q, E, F, Ctrl, R (actions are named `slot_1`..`slot_5`). Never hardcode a key in UI text: use `InputLabels` (see HUD and UI); `k1_key_hint_scan_test` fails if you do. Tests should read keys from the InputMap or send `InputEventAction`s, never `KEY_1` and the like (`cast_input_6a_test` was red after 24530e4 for this reason).
- **Don't add per-frame allocation** in hot paths (`Player._physics_process`, `Enemy`, HUD): earlier reviews removed several. Use the `EffectPool`, not new nodes, for transient visuals. The held `CastPreview` is deliberately not pooled.
- **Enemy stats live in data.** The exported fields on `Enemy` scenes are only fallbacks (see `Enemy._apply_stats`).
- **Enemy HP bars:** `elite` and `boss` ranks always show their bar; the endless-arena `data/waves.json` has none; the shipped run rooms have one elite and the boss, which always shows `BossHpBar` (top centre) instead.
- **Acts and the save (MAP3).**
  - Use `stream_index()`, not `room_index`, for anything seeded per room, or act 2 repeats act 1's rolls. Use `run_room_label()` for "Room N of 30"; `room_label()` still says "Room 10 of 10" on a three-act run.
  - A test that starts a run must pin `RunSession.acts_override = 1` (or `--acts=1`) to keep the one-act meaning, as the one-act suites and capture presets do.
  - A test that touches the save must set `RunSave.persist_override` and a `user://tests/` path, and call `RunSave.reset()` after. Tests that open `ClassPickScreen` can leave the tree paused; 11 suites reset it in `after_test` (since BD3a `GamePause.reset()` also unpauses the tree, so the guard is belt and braces).
  - Known gap (qa, MAP3): the HUD plate reads "Act 1 of 3" behind the Act 2 screen until the next room. (The MAP3 gap about a save with bad `hp` or `rejects_remaining` was closed in BD3a: `RunSave` refuses it.)
- **Run state is a static.** `RunSession.current` survives scene swaps on purpose, so tests and tools that start a run must call `RunSession.clear()`. A new per-room reset belongs in the fresh scene; something that must carry over belongs in `RunState` (and its `to_dict`/`from_dict`). `Health.damage_immune` is set at room clear and must not leak into the next room (the reload soak checks it).
- **The starter deck is exactly at the minimum.** each character's `starting_deck` has 3 unique cards per slot, so `DeckRules.can_remove` blocks every starter card until a pick adds a 4th unique or a duplicate in that slot; early rest rooms are heal-only. Editing a `starting_deck` (now in `data/characters.json`) must keep `deck_rules.json` satisfied (`CharacterDatabase.validate_table` checks it). `--full-deck` is the way to reach the removal grid in a capture.
- **A choice is state, not UI.** An open choice lives in `RunState.pending`/`offer`. Anything that frees or reloads the scene mid-choice must leave them alone; only `choose` (or `continue_to_next_room(force = true)` in tests) clears them. `RunState.from_dict` drops an unknown `pending` (logs an error) and, since MAP3, validates the other field types (see Acts and the save).
- **Offers are seeded by (run seed, room index) and the current deck,** on their own RNG stream, so a change to the deck changes later offers but never touches the spawner or player RNG. Candidates are sorted by id before the draw.
- **Wave-sim pick rates cover all database cards,** so cards the bot never picked show as `NEVER CAST`. That is expected, not a defect.
- **Seeded baselines use the endless arena.** The wave_sim seed hashes depend on `Main.tscn`. The `tier|enemy` encoding in `WavePlan` is built to leave them unchanged.
- **`TrainingDummy`** (`scenes/debug/`) is not in `Main.tscn`; some tests instantiate it.
- **Name rows:** card names use `fit_padding` 12 and line spacing 0 so two-line names fit; a test pins every card name at 720p, 1080p and 1440p.
- **One shader lives in `src/player/`** (`player_occlusion_cue.gdshader`), the other in `assets/shaders/`.
- **Boss fairness is checked by data tests.** Edit `data/bosses.json` and run `m3c_boss_test`: it checks every shipped attack can be escaped by walking or the dodge (a test, not load-time validation; the load only enforces `rules.min_telegraph` and shape).
- **A container resets child scale on sort.** Anything scaled inside a `Container` (the reward panel's fit) must be re-applied on `sort_children`.
- **All damage must go through `Health.take_damage`.** Subtracting from `current_health` directly skips armor and resistance; a static audit test (`a1_qa_test.gd`) fails if source code does it outside `Health`. Pass the `source` so penetration and `damage_dealt` work, and pass the right `damage_type`: a new physical-like type belongs in `data/armor.json` `non_elemental_types`, otherwise it is treated as elemental.
- **Armor and resistance parity.** Each tier's armor and resistance must give reductions within 2 points (`ArmorConfig.PARITY_TOLERANCE`); this is checked at load and by tests. Change one without the other and a test fails. `tiers.boss` in `data/run.json` is still unused by the real boss (it has its own armor in `bosses.json`).
- **"All elements" boss text** is judged against the game's element list, so it is only right while the elements are uniform; a second element with a different resistance changes it on purpose.
- **Last class pick persists (windowed only).** `user://last_class.json` preselects the class, so captures must pass `--class`. Headless runs, tests and sims never read or write it.
- **Scenario body colour:** a scenario's `character` key sets the Wizard's pools and attacks, but the scenario body stays Rogue-coloured (known issue).
- **Presets are only the starting deck.** Rewards change a `--deck` / sim `-Deck` deck as the run goes on (physical-rogue goes from 2 to about 4 Fire cards by the boss), so sim comparisons dilute over a run. `--deck` is silently ignored with `--scenario` and in the arena.
- **`CombatEvents` is the last autoload and is reached through `CombatLink.events()` in any script the bot sim compiles** (BD1). The history is empty after a reload (the soak asserts it). A projectile that fails its condition is spent; a dash's path hits ignore target conditions; zone ticks re-check per tick.
- **BD1 known gaps (qa):** `CastPreview`, and the bot outside `-Plan`, treat conditional effects as unconditional; a buff aura outlives its spent charge; a delayed aoe with neither `anchor` nor `max_range` telegraphs at the cast spot but hits at the caster (pinned by a test). None affects a shipped card. `JsonDataTable.get_entry` crashes (loudly) on a non-object entry. `slice6_qa_test`'s same-seed crowd test was flaky (pre-BD1); BD2 mitigated it, see the Relics and flaky-test items below.
- **Relics (BD2).** Relic effects run deferred (end of frame), not inside the event that caused them, so a test that checks an effect must `flush()` the manager or wait a frame. The recursion guard covers only work inside the deferred flush: a relic-spawned projectile or zone that hits later runs at depth 0 (qa; nothing shipped both allows relic origin and spawns something delayed, so nothing loops today, but test it before adding such a relic). A hit relic with no origin filter can fire on ticks of a relic-applied Burn (bounded by the depth of 1). Counters and cooldowns reset each room. Relics roll chances on `player.status_rng`, so holding relics shifts card status rolls and the seeded run baselines. (MAP3 fixed the old `RunState.from_dict` crashes on a bad `offer` entry and the unchecked relic lists.) The straight run's relic room uses 0-based `relics.relic_room` `first: 2, last: 8` (on-screen rooms 3 to 9); a map run uses `relic_room` nodes instead. `RunConfig._validate_relic_text` does not format-check `swap_line_one` (a missing `%s` would error at runtime). The pause relic list draws straight over the 3D scene (no backing panel; qa, cosmetic).
- **One known flaky test.** `slice6_qa_test` same-seed crowd: the first crowd run in a suite differed from the rest from tick 73; a discarded warm-up crowd run now precedes the compared runs (about 1 failure in 10 isolated runs before, 0 in 15 after). The other old flake, `c1e_cues_test` "ghost look lasts until the player is clear", was a test setup race and is fixed (eee5813, MAP1 qa: 24/24 under CPU load). If a full run fails on the crowd test, re-run that suite alone before suspecting your change.
- **The map is on by default (MAP1), so a test or tool that assumes the straight run must pin it:** `RunSession.map_override = 0` in `before_test` and `-1` in `after_test`, or `--no-map` / `-NoMap` / the soak without `-Map`. Room numbers mean different nodes on a map (`--run-room=N` follows the first route). The straight-run capture presets pass `--no-map` since MAP2. Two tests in `map1_qa_test` stay skipped (the `from_dict` node-pending soft lock and negative gold) until MAP3's save robustness; the generator script error (`:59`) and the dead `RelicProgress._triggers` fallback were fixed in MAP2.
- **Map generation is a rejection sampler.** `max_attempts` counts type draws only; grid redraws for shape rules are not counted (bounded at 5000). Since MAP2 (`min_rest` 1, rest weight raised, `max_attempts` 1000, `TYPE_DRAWS_PER_GRID` 40) the 1000-seed sweep's worst case is 479 of 1000 attempts (qa), so there is limited headroom: a weight or window change can push seeds over. A type with no candidate left fails the draw (no fallback to combat). Any generator change moves every map and the `map_*` / `merchant_*` capture presets' seeds and node ids. The map seed is its own stream derived from the run seed, so a change to the generator changes every map but not combat or offers.
- **Merchant gotchas (MAP2).**
  - The shop's stock is state (`RunState.merchant_visit`), not UI: a reload mid-visit must keep it. An old save whose stocked relic id is gone returns `unknown_relic` instead of crashing.
  - Relic prices (`relics.prices`), `map.json` `relic_route` and `estimate.merchant_prices` move together (D41 = B, MAP3: prices 80 / 120 / 170 for three acts); change them together and re-run the sim and the map sweep.
  - Request for Quotation is in about 79% of shops because the shop-only slot is tier-weighted (BD3). Liquidate Assets' stat refreshes only on a relic buy. `Merchant.items()` can show a relic as buyable at the cap with nothing to give up (unreachable until boss relics exist). `--run-gold` may ignore a non-integer value silently (unverified; `--run-node` refuses one since MAP3).
  - Some comments still say the merchant ships off (`RunController.gd` ~242-243, `MerchantSwitch.gd` header), and `tools/run_wave_sim.ps1` says `first`/`random` buy a relic. Trust the code: `MerchantPolicy` buys a removal, then a card.
  - The shop opens focused on a purchase on purpose (eyes item 51).
- **Scenario `--class`:** a scenario with its own `character` plus a different `--class` is refused with exit 2 (`Scenario.class_problem`). Bot-sim hashes with and without `-Plan` are separate baselines (README, Last verification).
- **BD3a gotchas.**
  - **The sim bot aims through `aim_point_override`.** It was ignored until a9d56fc, so every bot number from before is stale (SIM1 re-baselines). A new facing-dependent mechanic needs a test that sets the override, because a bot without it faces a fixed direction.
  - **Stack cap and tick rate come from the latest applier,** not the first, and a cap that drops later (a buff ends) leaves existing stacks until the status ends. A reapply below the cap adds a stack; `status_applied` stays silent on it.
  - **A detonate is not a status source.** `CardSummary.status_ids` skips it, so it does not count for `requires.status_sources` or the offer lean. Its kill ends the status as `detonated`, so Pyre Insurance never fires from it but Severance Package still counts the kill.
  - **Never pass a freshly built node through `call_deferred`.** If the owner frees first, the node leaks (orphans fail the suite's exit code) or Godot logs "Error calling deferred method". Build it inside the deferred function (`EnemyHpBar`'s stack label).
  - **Any new Rogue pool card moves the seeded hashes** (arena, `-Plan`, bot sim); removing the card files restores the old values exactly. Rebaseline and say so in the README.
  - **The lean's starter exclusion is a copy count, not a per-card flag,** so nothing extra is saved: a starter card pruned and re-picked counts as starter.
  - **Offer fit:** the "In slot" list is capped (`slot_now_max`, then "+N more") because an unbounded list broke `offer_fit_test`; a long new card name can still break it.
