## Blocking issue

**B1. `MeleeReachCue` leaks a node for every non-arc light attack (the Wizard).**
- `src/ui/MeleeReachCue.gd:18`: `var _band := MeshInstance3D.new()` runs at field init. `setup()` returns early at `if not _armed: return` (line ~46) before `add_child(_band)`, so for the Wizard the `MeshInstance3D` never gets a parent and is never freed.
- Effects: 20 orphans in the suite (19 in `w1a_test`, `w1a_qa_test`, `w1a_ux_test`, i.e. every test that loads a Wizard Main, plus 1 in `pl2_ux_test::test_the_rogue_gets_the_cue_and_the_wizard_does_not`) -> runner exit 101 instead of 0 (ux saw the same; ux's "w1a_test.gd:246" is one of the 19, and it is not a baseline orphan: baseline has 0). Engine ERROR/WARNING at exit of a Wizard headless run. A real runtime leak of one node per Wizard room load and per Try again.
- Repro: `godot --headless --path . --quit-after 2400 -- --class=wizard` prints the two lines above; or run `tests/unit/pl2_qa_test.gd` (new, below).
- Verified fix (scratch worktree, not applied here because I don't edit source): in `setup()`, when not armed, free the band before returning:
  ```
  if not _armed:
  	_band.free()
  	return
  ```
  With it: `w1a_test`, `w1a_qa_test`, `w1a_ux_test`, `pl2_ux_test` all report 0 orphans, the Wizard soak is RELOAD CYCLE OK, the Wizard headless run is clean. (Creating the band lazily inside the armed branch works too.)
- Regression test: `tests/unit/pl2_qa_test.gd::test_loading_a_wizard_main_leaves_no_orphan_nodes`. It **fails on HEAD** ("a Wizard Main leaked 1 orphan node(s)") and passes with the fix. Until gameplay/ux applies the fix the suite at HEAD has exactly this 1 failure; that is intended.
