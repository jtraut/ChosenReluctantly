## Pick-screen risks
- **Pause leak:** no. With the screen open, qa tapped all 5 slot actions, dodge, light and heavy for 0.6 s of real time. The player did not move, no enemy spawned, every slot cooldown stayed 0, and after the screen closed no press was replayed (all cooldowns still 0). So the spawner, wave timer and slot cooldowns are really held. New test.
- **Esc and Space behind it:** Esc does not open Settings (the pause request is refused because GamePause is already paused), does not release the hold, and a second Esc does the same. Space is swallowed by the screen (existing test). New test for Esc.
- **Stuck with no screen and a paused game:** not reproduced. Same-class confirm resumes. A different-class confirm keeps the screen up until the scene swap, and the fresh scene is unpaused (checked after a real Enter and after a real click). `_exit_tree` resumes if the screen is freed while holding the pause. `GamePause.reset()` on a swap covers the confirming case.
- **`_confirmed_run` static across Try again:** it holds the old RunState object. Try again makes a new RunState, so the screen opens again; qa's test also covers Try again after a class change (preselects the new class). A scene reload of the same unfinished run state (a soak reload) does not re-ask, which is intended.
- **Arm delay:** a real Enter before 0.4 s does nothing and the room stays held (new test); after the delay it confirms.
- **Fit at 1024x600:** fits, scale not shrunk below the 0.7 floor; screenshot checked.
- **Real input:** the ux tests called methods. qa's new tests drive real events through `Input.parse_input_event`: Enter (same class), key 2 then Enter (restart as the Wizard, 26 HP, same seed, no second screen, unpaused), and a left click on the Wizard card.
