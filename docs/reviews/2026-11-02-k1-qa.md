It is the menu accept, not the dodge binding, so it is allowed (and allowlisted by exact string in the scan); if Space is ever unbound from menu accept, this text goes stale. ClassPickScreen "1 / 2 or the arrow keys" is positional menu navigation (allowed per game-lead).
- `InputBindings.bindings_changed` is only emitted by `load_bindings` today; there is no runtime rebind UI. Tests emit it manually after editing the InputMap, which is the right contract for a future rebind screen.
- The conflict message is a push_error only. It shows in the console at startup but the game still runs; fine per the brief.
- `RunOptionCard.slot_key_for` still returns a 1-based HUD order index (kept for column ordering and documented as not a key). Not a bug, just easy to misuse.
- No DECISIONS.md entry for K1; none required unless gameplay-dev made judgment calls (e.g. conflict handling does not quit).
