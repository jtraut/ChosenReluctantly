## Carry-overs and non-blocking issues

1. **gameplay-dev (small): remove `"relic_room": []` from `data/run.json` `rooms`** (section 3). With it gone, the generator test (now fixed) and the full suite pass. A stopgap comment in DECISIONS "BD2-B" should drop with it.
2. **game-lead to route an owner: `c1e_cues_test > test_the_ghost_look_lasts_until_the_player_is_clear_of_enemies` is flaky and predates BD2.** It fails at `c1e_cues_test.gd:199` (`player.is_pass_through()` false: the enemy placed 0.2 m inside the player has already been pushed out by the time of the check). Measured: **3 failures in 14 isolated runs at 3b1ac07 (before BD2)**; 1 in 6 isolated runs and 1 in 3 full suites at HEAD (the other two full runs were green). Not caused by BD2 (the test and the code it touches are unchanged). It will trip a full-suite run about once in 5 to 10 runs, like the slice6 one did.
3. **gameplay-dev, and a sequencing note for game-lead: `RunState.from_dict` crashes on `String(entry)` for an `offer` entry that is null, an array or an object** (`RunState.gd` line 151, "Invalid call. Nonexistent 'String' constructor"). It is shared by the card offer and the new relic offer. Repro: `data["offer"] = [null]` (or `[["x"]]`) in a dict from `RunState.new_run(...).to_dict()`, then `RunState.from_dict(data)`. This is already ROADMAP 3d item 6a, but 3d comes after MAP1-MAP4 and the save file arrives in MAP3 (D32), so a save file would exist on disk before the crash is fixed. Suggest moving 6a into MAP3. My fuzz test skips only that one shape and carries a comment pointing here. Related, same area: `from_dict` does not check that `relics` and `relics_given_up` are disjoint, that `relics` fits the cap, or that the ids exist; a hand-edited save could break those invariants (an unknown id is reported loudly by `RelicManager`, so it is loud, not silent).
4. **gameplay-dev, BD3 note: the chain-depth cap only covers work done inside the deferred flush.** The depth travels with the queued job, so an aoe's synchronous hits are capped, but a relic-spawned projectile or zone that hits later runs at depth 0. No shipped relic both allows relic origin and spawns something delayed (Pyre uses an aoe), so nothing loops today. Worth a test before BD3 adds relics that spawn zones or projectiles.
5. **ux, cosmetic:** the pause relic list is drawn straight over the 3D scene at 1024x600; the player capsule shows through an entry (`bd2-ux-pause-1024x600.png`). A panel backing would fix it.
6. **game-lead, informational:** the Wizard's relic damage is 1.15% of the total (Pyre 194.8 plus Heavy Sigh 39.6 of 20450), a hair above the "under 1%" in the dev report (the per-relic percentages each round to 1% and 0%). The Rogue's is 0.45%. Not a defect, but the claim should read "about 1%".
7. **Test hygiene, mine:** `tools\run_tests.ps1` takes about 8 minutes now (it was 7 min 45 s at 1413 cases).
