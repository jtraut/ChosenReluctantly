## Code review
- Typed GDScript throughout; `--press` absent means `presses` is empty, no node is added, no effect on the normal path.
- Aim override: cleared on `aim_off`; it lives on the Player instance and the Player is recreated with each fresh Main, so it cannot leak across Try again or room changes. If `aim_nearest` is on and no enemy is left, the override keeps its last point (documented).
- **TL1-1 (non-blocking bug): held actions are not released when ScriptedInput leaves the tree.** `Main.swap_to_fresh_scene` replaces Main on every room change, reward pick and Try again, and ScriptedInput is a child of it. `_releases` dies with it, so a hold in progress leaves the action pressed in `Input` (parse_input_event press with no release). The new Main's ScriptedInput does not know about it. The player in the next room walks on its own until the key is next sent a release. Not hit in the real runs above because every hold ended before the capture. Regression test `test_freeing_scripted_input_mid_hold_releases_the_action` in `tests/unit/tl1_qa_test.gd` **fails today (confirmed, 1 failure)**. Fix: an `_exit_tree` that sends `_send(action, false)` for every pending release (about four lines, game-lead to route to gameplay-dev). Until fixed, the test is red; the other five tests in that file pass.
- Same cause, second effect: every fresh Main re-parses `--press` and starts its script at t=0. See the fitness finding.
- Player death mid-hold: the release timer is on ScriptedInput (process mode ALWAYS), not the player, so holds release on schedule. Fine (covered by reasoning; not run).

## Fitness for the Milestone 3 playtest (finding, not a FAIL)
**Not enough as it stands for a full three-act run per class.** It is enough to play one fight in one room per capture. Missing, in order of importance:
1. The script restarts at t=0 in every new Main (every room, reward pick, Try again), and the process is one capture (`--screenshot-after` times are relative to launch). A single `--press` list cannot span rooms. Needed: a run-wide clock or a per-room script, plus the TL1-1 release fix.
2. No UI input: the map node choice, reward/shop/event/class-pick buttons. `--run-auto-choose` covers option ids only, and its counter (`_auto_chosen`) is per scene instance, so it is likely to restart as well (not verified). Nothing drives the map screen (no `--press` step reaches UI focus/accept, and the move actions do not choose a node).
3. No reactive behavior: the playtester cannot say "move toward the nearest enemy" or "dodge when hit", only fixed times; aim follows the nearest enemy but movement does not. Rooms beyond the first have different enemy layouts, so fixed-time scripts will mostly miss.
4. Captures are windowed, one per launch, with fixed sample times; no way to capture on room clear or at an event.
Suggestion for a follow-up (TL2): a headless or windowed "autoplay" mode (move toward nearest enemy, attack and use slots on cooldown, pick the first reward option, pick a map node by simple rule) that survives scene swaps, which also is what the playtester needs for three acts per class.
