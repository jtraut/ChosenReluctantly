## Blocking issues

**B1. Full suite red at handoff (fixed by qa in c7269ea).** `w1a_test` Rogue-colour pin, see above. Reproduce on adf2e8a: `powershell -File tools\run_tests.ps1` (or `GdUnitCmdTool.gd -a res://tests/unit/w1a_test.gd`). Already fixed; listed because ux's "touched tests green" missed a test that pins data ux changed. Process suggestion: when a data value in `data/characters.json` or `data/ui.json` changes, grep `tests/` for the old literal.

**B2. The map beat is not skipped in watch mode, contrary to item 7 and DECISIONS ("hosts the game as a script").** `MapScreen.human_session()` tests `DisplayServer != headless and main_loop.get_script() == null`. `tools/run_wave_sim.ps1` runs `res://tools/WaveSim.tscn` (a scene, `extends Node`), not a `-s` script, so in a windowed watch run the main loop has no script and the beat is on. Reproduction (committed probe, c7269ea):
- `godot --path . res://tools/ProbeHumanSession.tscn` prints `human_session=true` (windowed, scene-hosted).
- `godot --headless --path . res://tools/ProbeHumanSession.tscn` prints `human_session=false`.
The existing test only proves the false case under the test runner. Impact is small (a single-option pick is the same node the bot would take, no RNG, headless SIM is unaffected so every hash and SIM1 count is intact), but the brief states "watch mode skips it" and a beat that rewrites the line text and can race the bot's pick on a watched run is a spec violation. Fix suggestion for ux/gameplay-dev: a static opt-out the wave sim sets (or a launch-arg check) instead of inferring from the main loop, and a test that sets it.

**B3. Crowd digits overprint in every pile capture (item 4).** In all nine `crowd-pile-*` frames each ring slot reads as an orange "12" with a smaller white "1" printed over its first digit (two numbers, presumably a Fire hit and a physical/Bleed tick, at one spot, different merge keys). It is the same class of defect as item 1 and makes the digits read as "1" glitches. Several ring slots also sit on an enemy body (right side at about 770,298 in `crowd-pile-1280x720_2`), and the Healing Potion "+9969" lands on the HP bars. Reproduce: `ux1b_crowd` scenario via `tools\capture_screenshot.ps1` (see `tools/capture_presets.json`) or open the captures. ux should confirm whether the second number is intended, then merge or offset it, and add a test that two numbers from one enemy never share a spot.
