## 2. Watch-mode fix

Code reading (`tools/wave_sim.gd`):
- Every change is behind `_watch != null` (`_watch_physics_rate()` is called only when a watch dir is set and `--legacy-cadence` is absent; the `physics_frame` await only when `_watch != null and not _legacy_cadence`). Headless takes the old `process_frame` path. Confirmed by the four hashes and SIM1.
- Restore (`physics_ticks_per_second = 60`, `max_physics_steps_per_frame = 8`, `use_accumulated_input = true`) sits after `_watch_end` at the end of `_run_whole`. All the in-loop failure paths (`_fail` + `break`: room did not load, choice refused, act did not advance) fall through to it, and `_watch_end`'s early return does not skip it. A script error or crash ends the process, and engine settings do not persist, so there is nothing to restore on that path. So the restore is covered for early exits that return control; there is no `finally`. Restore values are hardcoded, not saved-and-restored; they equal the engine defaults and the project sets neither (project.godot has no physics tick override), so this is correct today.
- Multi-run: each run re-raises at its start and restores at its end.

## 3. ScriptedInput carry-across-swaps

- Debug-only: `carry_across_swaps` is set in exactly one place, `Main._setup_debug_capture`, inside the `presses` branch, which needs `--press=` user args. A normal launch returns at `args.is_empty()` and never creates a ScriptedInput. No effect on normal play.
- Static state: `_carried` is written only by instances with the flag, is keyed by `str(presses)` (a different script does not resume it), and `reset_carry()` clears it. Plain instances never write or read it. Checked by three new qa cases in `tests/unit/tl4_qa_test.gd` (non-carrying instance leaves nothing; a different script does not resume; the same script resumes with elapsed 0.5 and next 1). The existing TL3b case covers the fire-once and the no-carry replay (count 2) behaviour. All pass.
- `-Preset map_beat_skip` run for real (windowed, 2.0 s shot): exit 0, the log has exactly one `ScriptedInput: t=1.81 press any_key`, and the PNG shows the Head of Facilities fight screen, not the map. Nit 1 is fixed.

## 4. Job guard

- Refused launch: `powershell -File tools/capture_screenshot.ps1 -Scenario "" -Extra '--run-hp=abc'` exits 2 from the Bash tool (and the suite's own case asserts it through `-Command`).
- Hard kill: I started `run_wave_sim.ps1 -Seed 7 -Seconds 200` through `Start-Process`, confirmed 2 new Godot processes (console and its child), `Stop-Process -Force` on the wrapper, and 3 s later 0 survivors. Verified for real, not only through the test stand-in.
- Agent and README call style (`powershell -File ...` from the Bash tool, ~20 wrapper launches including 12 in parallel and 4+4 windowed in parallel): nothing hung or was killed unexpectedly. Nested job under the Bash tool works (the tool's own job did not block the join). Exit codes survive.
- Dot-run caveat: dot-sourcing the wrapper in an interactive shell would put that shell in the job, and closing it would kill its children. The README documents `powershell -File`, so in practice it does not matter. Not blocking.
- `tools/run_tests.ps1` is not job-guarded (not in scope). When I killed a stray `run_tests.ps1` wrapper by pid, its Godot console and windowed children survived and had to be stopped by pid. Same orphan class as the TL3b nit; the brief only asked for the two wrappers.

## Non-blocking issues

1. Restore coverage is by source-string tests only (`test_watch_mode_raises_the_tick_rate...` counts `Engine.physics_ticks_per_second = ` occurrences). It proves the restore line exists, not that it runs. A try/finally or save-and-restore of the original values would be sturdier. Low risk, since the process exits at the end of the sim.
2. Two or more windowed watch runs in parallel share `user://run_save.json`: seed 3 of the Scale 1 batch and the Scale 4 batch each logged `WARNING: RunSave: could not move the save into 'user://run_save.json'` (8 lines in one run). The wrapper reports engine warnings, so a parallel windowed batch can exit 1 with a win. It is a file-move race between concurrent processes (my 4-at-once launch), not caused by TL4 (the 12-way headless batch had none). Run watched runs one at a time, or the wrapper could pass a scratch profile path. Worth a README line.
3. `run_tests.ps1` can orphan Godot if killed (see section 4).
4. ScreenshotCapture restarts its clock on a scene swap (carried in gameplay-dev's Remaining), so `map_beat_skip`'s 2.0 s shot is 2 s after the swap. Not a bug for the preset's purpose.
5. 4 parallel windowed Scale 1 runs took about 9-10 min wall each, not real time of 30 min, since a won three-act run is about 8 game minutes. The README's "about half an hour" at -Scale 1 is stale; measured 530-590 s wall.
